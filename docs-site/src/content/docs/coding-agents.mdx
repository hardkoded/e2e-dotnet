A coding agent such as Claude Code, Codex, or Cursor can write, run, and debug e2e tests. It learns e2e from the skill, uses the app through the `e2e mcp` server, and reads the output of a failed `dotnet test`. This page ports upstream's `docs/coding-agents.mdx`. Start with `e2e init`, or run each step below as a separate command.

## Scaffold with `e2e init`

```bash
dotnet tool install --global E2E.Cli
e2e init --yes
```

`e2e init [directory]` scaffolds the e2e side of a project. It never overwrites an existing config; a rerun refreshes stale skill copies and the e2e entry of existing MCP files. It asks the questions no flag answered: the engines, the model gateway (and the endpoint of an OpenAI-compatible one), where to install the skill, and where to register the MCP server. Then it lists the changes and asks to apply them; leaving a question or declining the plan writes nothing. If a skill directory is a symlink, it asks before replacing the link with a copy (or with a link to the other copy), and declines by default; declining skips only that replacement. Under `--yes` it never asks and leaves such a symlink alone. Without a terminal it needs `--yes`. It writes `e2e.config.json` (a web target and a model gateway), installs the skill into `.agents/skills/e2e-dotnet` (with `.claude/skills/e2e-dotnet` as a symlink to it), registers the MCP server in `.mcp.json` and `.cursor/mcp.json`, and adds the `.e2e/` outputs to `.gitignore`. It creates no test project and edits no `.csproj`; the closing line points at `dotnet test`. Re-run it after an upgrade to refresh the skill and the MCP entries. A re-run keeps the settings you added to the e2e entry of an MCP file, and never writes through a symlink.

| Option | Description |
| --- | --- |
| `[directory]` | Where to scaffold; created when missing. Default: the working directory. |
| `-y`, `--yes` | Ask nothing. Each answer not given as a flag takes its default: the web engine, the Vercel AI Gateway, the skill and the MCP config in both locations. |
| `--engine <ids>` | The engine for a new config: `web`, `mobile`, or `none`. One target only. |
| `--gateway <id>` | The model gateway for agent steps in a new config: `vercel`, `openrouter`, `openai-compatible`, `chatgpt`, `copilot`, `opencode-console`, `grok`, or `none`. The config names the matching `provider`. |
| `--endpoint <url>` | Base URL for `--gateway openai-compatible`, and implies it. HTTPS, or HTTP on a loopback host. Default: `http://127.0.0.1:11434/v1`. |
| `--skills <dirs>` | Where to install the agent skill: `.agents/skills`, `.claude/skills`, or `none`. Comma-separated or repeated. |
| `--mcp <files>` | Where to register the MCP server: `.mcp.json`, `.cursor/mcp.json`, or `none`. Comma-separated or repeated. |

`--engine`, `--gateway`, and `--endpoint` apply only to a new config. Exit code 2 means an unknown flag value, no terminal and no `--yes`, a directory argument that is a file, more than one engine chosen, the skill missing from the installed tool, or an invalid MCP file. A file or directory in the way of the skill, and a symlink that cannot be replaced, are warned about and skipped; a replaceable symlink asks first, except under `--yes`, which leaves it alone.

For a subscription gateway, sign in before the first run with `e2e login <provider>`. See [COMPATIBILITY.md](/compatibility/#coding-agents) for what the port leaves out.

## Install the skill

```bash
npx skills add hardkoded/e2e-dotnet --skill e2e-dotnet
```

`e2e guide [topic]` prints the same skill from the installed `E2E.Cli` tool. For an agent that needs a pointer, add this line to your project instructions:

```md
End-to-end tests use e2e; read .agents/skills/e2e-dotnet/SKILL.md before writing or running one.
```

## Let the agent use the app

`e2e mcp` gives the agent a live session on your app. It checks its locators against the screen before it writes them. Install the tool, then register it once:

```bash
dotnet tool install --global E2E.Cli
claude mcp add e2e -- e2e mcp
```

See the [README](/guide/#coding-agents-mcp) and [COMPATIBILITY.md](/compatibility/#mcp-server).

## Generate a verification skill for your app

The e2e skill teaches the runner, not your app. The `create-verification-skill` skill writes a project-local `.agents/skills/verify-<app>/` skill that does, and tests it one time before it hands over.

```bash
npx skills add hardkoded/e2e-dotnet --skill create-verification-skill
```

Then ask the agent for `/create-verification-skill`.

## Migrate an existing suite

The `migrate-to-e2e` skill moves a Playwright .NET, Selenium .NET, Appium, Cypress, Detox, or Maestro suite to e2e one slice per session. The old suite keeps running beside the new tests, so you can stop after any session.

```bash
npx skills add hardkoded/e2e-dotnet --skill migrate-to-e2e
```

Then ask the agent for `/migrate-to-e2e`. It ports the slice you pick as NUnit or xUnit v3 tests and runs each ported test three times on every target. A `MIGRATION.md` file records progress for the next session. Optionally, the agent plants a temporary bug in the app, such as a wrong checkout total, and checks whether both suites fail on it. The agent deletes an old test only when you confirm.

Upstream reads a migration guide for the runner first (`docs/migrate/*.mdx`). The port has no such guides, so the skill reads the e2e skill's topics instead. See [COMPATIBILITY.md](/compatibility/#verification-skill).
