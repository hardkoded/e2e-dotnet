_Released November 8, 2026_

v0.9.0 brings 225 pull requests, one week after v0.8.0. Highlights:

- Run agent steps on Claude Code or Codex, with their own login.
- Post the test results as a pull request comment from GitHub Actions.
- Rerun only what failed.
- Check the setup with `e2e doctor` before a run.
- Get a ready-to-run test project from `e2e init`.
- Web locators that behave like Playwright's, backed by hundreds of ported Playwright tests.

```bash
dotnet add package E2E --version 0.9.0
dotnet add package E2E.NUnit --version 0.9.0   # or E2E.XUnit.V3
dotnet tool update --global E2E.Cli
```

> ⚠️ This release has breaking changes. See [Breaking changes](#breaking-changes) before you upgrade.

## Highlights

### Run steps on your coding agent (`E2E.Acp`)

`E2E.Acp` runs `Agent.ActAsync` and `Agent.AssertAsync` on Claude Code or Codex over the Agent Client Protocol. The agent signs in with its own login, so you need no model provider. The runner records every action, so steps still replay from the cache without the agent. The agent gets only the step tools: its own file, shell, and web tools are off, and a tool of its own fails the step with `POLICY_DENIED`.

```bash
dotnet add package E2E.Acp
npm install -D @agentclientprotocol/claude-agent-acp   # Node must be on the PATH
```

```csharp
public abstract class AppTest : E2ETest
{
    private static readonly IStepExecutor Claude = AcpExecutor.ClaudeCode(new AcpAgentOptions { Model = "sonnet" });

    protected override IStepExecutor? AgentExecutor => Claude;
}
```

Use `AcpExecutor.Codex()` for Codex, or `AcpExecutor.Create(command, args)` for any other agent that speaks ACP. [Your coding agent guide](/features/acp/)

### Pull request comments (`E2E.GitHub`)

`E2E.GitHub` posts the results as one pull request comment from GitHub Actions, writes the job summary, and updates the same comment on a rerun. Failures come with their step, the line to look at, and links to the evidence.

Reporters now come from `e2e.config.json`:

```json
{ "reporters": ["E2E.GitHub.GitHubReporter, E2E.GitHub"] }
```

Give the workflow `pull-requests: write` and pass `GITHUB_TOKEN: ${{ github.token }}` to the test step. [Pull request comments guide](/integrations/github/)

### Rerun only what failed

`E2E_LAST_FAILED=1` reruns the tests the last run did not pass. Every other test skips itself. The GitHub comment folds the rerun into the previous run, so it still shows the whole suite.

```bash
dotnet test
E2E_LAST_FAILED=1 dotnet test
```

Or override `LastFailed` on your `E2ERunFixture`. [Test filters guide](/docs/test-filters/)

### Check the setup with `e2e doctor`

`e2e doctor` checks that `e2e explore` and `e2e mcp` can start here, without starting anything: the config, each target's engine (browser installed, devices, app path), and the model each agent resolved to. `--check-model` calls each model once, and `--json` prints a report for scripts.

```bash
e2e doctor
e2e doctor --check-model
```

[e2e doctor guide](/docs/doctor/)

### A test project from `e2e init`

`e2e init` now creates the test project too: a `.csproj` with the packages at the tool's version, and an `ExampleTests.cs`. In a folder that already has a project, it adds only the missing package references.

```bash
e2e init MyApp.E2ETests                        # NUnit
e2e init MyApp.E2ETests --framework xunit --install
e2e init --example TodoMvc my-sample           # start from a sample
```

[Coding agents guide](/coding-agents/)

### Accounts and several targets in the config

`credentials` declares test accounts. The password is a secret and is redacted. `Credentials.User(name)` reads the account in a test, and `e2e explore` and `e2e mcp` sign in with them. `targets` can list several entries, each with its own `name`.

```json
{
  "targets": [
    { "name": "web", "platform": "web", "app": { "url": "http://127.0.0.1:4173" } },
    { "name": "ios", "platform": "ios", "app": { "bundleId": "com.example.app" } }
  ],
  "credentials": { "admin": { "username": "admin@example.com" } }
}
```

Leave the password out of the committed file and set `E2E_USER_ADMIN_PASSWORD`, which wins over the config. Pick a target with `E2EFixture.TargetName`, `OpenHostOptions.Target`, or `--target`.

### Saved sessions on xUnit v3

Sign in once and restore the session in other tests, as NUnit could in v0.8.0.

```csharp
public sealed class Dashboard : E2ETest
{
    [E2ESetup("authenticate as admin", Saves = ["admin"])]
    public async Task Authenticate()
    {
        var admin = Credentials.User("admin");
        await App.OpenAsync("/login");
        await Screen.GetByLabel("Username").FillAsync(admin.Username);
        await Screen.GetByLabel("Password").FillAsync(admin.Password);
        await Screen.GetByRole("button", "Sign in").TapAsync();
        await SaveSessionAsync("admin");
    }

    [Fact, E2ESession("admin")]
    public async Task Opens_the_dashboard_directly() => await App.OpenAsync("/dashboard");
}
```

Test filters also work on xUnit v3 and on the mobile and Windows adapters.

### Value checks

`Expect.That(value)` checks plain values, with Jest-style matchers and partial matches:

```csharp
Expect.That(links, "the playground lists its pages").ToBeGreaterThanOrEqual(2);
Expect.That(payload).ToEqual(new { Id = Expect.StringMatching("^usr_"), CreatedAt = Expect.Any(typeof(DateTime)) });
```

[Value checks](/features/assertions/#value-checks)

### A sharper agent

- **Vision:** a `screenshot` tool and a pixel mode, so the agent can act on a canvas, a chart, or a screen the engine cannot read.
- **Point tools:** `tap_at`, `hover_at`, `drag_at`, `type_at`, `press_at`, `select_at`.
- **More verbs:** `long_press`, `right_click`, `hover`, `drag`, `dismiss_keyboard`, and `resize_viewport`.
- **Exploration:** `e2e explore` runs up to 100 steps and 2 hours, digs into edge cases once the main flows are covered, and prints through the list reporter.

### Inspect the replay cache

```bash
e2e cache ls      # one row per recorded step
e2e cache stats   # directory, entries, size
e2e cache clear
```

`E2E_NO_CACHE=1` runs every step live for one run, to try a new model.

### Web locators that behave like Playwright's

Hundreds of Playwright's own tests (selectors, locators, clicks, fill, keyboard, frames, routes, dialogs, downloads, screenshots) now run against the web engine. The fixes they drove:
- `GetByText` and `hasText` match the DOM text, and `GetByLabel` matches `aria-label`, `aria-labelledby`, and `<label>` text.
- `Browser.Locator("body")`, and any CSS selector, matches elements the agent's tree does not list.
- `Browser.EvaluateAsync` survives pages that replace globals such as `Array` or `JSON`.

### Also new

- BrowserStack App Automate real devices (`E2E.BrowserStack`). [BrowserStack guide](/integrations/browserstack/)
- `e2e mcp`: `start_recording` and `stop_recording`, `type_secret` with configured accounts, redaction of what user code prints, and registration for Codex in `.codex/config.toml`.
- The list reporter shows live progress, the code frame and video under a failure, agent step lines, and rows for skipped, warned, and repeated tests.

### Breaking changes
- **`E2E.Eas` is now `E2E.Expo`.** Update the package reference and `using E2E.Eas;`. `EasSimulators` and `EasSimulatorsOptions` are now `ExpoSimulators` and `ExpoSimulatorsOptions`, and the provider name is `expo-simulators`. There are no aliases (#982, #987)
- **Reporters come from `e2e.config.json`.** `[assembly: E2EReporter]` is removed. List reporters in `reporters` (#969)
- **`WaitForAsync` timeouts fail with `LOCATOR_NOT_FOUND`**, not `TIMEOUT` (#938)
- **`InputValueAsync` and `IsCheckedAsync` throw `ACTION_FAILED`** on an element that cannot hold a value or a checked state, instead of returning `""` or `false` (#1114)
- **`Browser.EvaluateAsync` returns plain JSON only.** A class instance such as a `DOMRect` fails with `INVALID_ARGUMENT`. Return `rect.toJSON()` (#1116)
- **Web text matching follows the DOM.** `GetByText` no longer matches a placeholder or the control a label names. Use `GetByLabel` or `GetByPlaceholder` (#1089)
- **`E2E.XUnit.V3` needs `xunit.v3.extensibility.core` 4.0.1** or later (#944)
- **`ReportExploreFinding.ArtifactId` is an artifact id**, not a file path (#966)
