This page ports the parts of upstream's `docs/reference/security.mdx` (tester-army/e2e, `17a2e46`, #1711) that cover behavior the .NET port has. Rules of features the port lacks (serial groups, the runner, `cache.store`, telemetry) have no counterpart here.

## Redaction

Text a model, a report, or a log would carry is redacted: a configured secret's value shows as its `<secret:name>` marker. Redaction matches strings, so these pass through:

- a value a secret provider returns, in titles and in an `e2e explore --changed-since` brief: both are redacted before any provider runs, so the provider's value is not yet known,
- on the web engine, a password field that a page script hides from e2e, for example by replacing `Element.prototype.matches`. e2e reads it as a plain field: the observed screen and `InputValueAsync` show its value, and a failed `ToHaveValueAsync` prints it. `GetAttributeAsync` and `ToHaveAttributeAsync` do the same when the HTML `value` attribute holds it. A configured secret's value is still `<secret:name>`. Screenshots still mask the field, unless it is in a closed shadow root and the page also replaces `querySelectorAll`,
- a screenshot, including one sent to the model: it masks secure fields only, after a secret fill too,
- video: it masks nothing and is labeled `redaction: "incomplete"`,
- in an `e2e explore --changed-since` brief, a run of fewer than 8 characters of a value, such as a short last line of a multiline key that git prints on a line of its own.

Error messages and skip reasons in a report only lose their ANSI escapes, and each control character other than tab, newline, and the `\r` of a `\r\n` line break becomes U+FFFD (a lone `\r` included), so treat them as untrusted. A reason from a test filter also has its whitespace collapsed, so its `\r\n` becomes a space.

## Browser sandbox

On macOS and Windows, Chromium launches with its OS sandbox on, which helps contain a renderer exploit on a page the agent reaches. It does not prevent sandbox escapes or Chromium vulnerabilities. On Linux the sandbox is opt-in, because root, most containers, and Ubuntu 23.10+ block the user namespaces it needs: set `WebEngineOptions.ChromiumSandbox = true` on a host that allows them. `WebEngineOptions.ChromiumSandbox = false` turns it off elsewhere. A browser reached through `Connect` or a provider is launched by its host, and Firefox and WebKit have no such option, so none of them read it. A sandbox that cannot start fails the launch with `ENGINE_FAILURE`, naming the option.

## MCP and explore

| Entry point | Rule |
| --- | --- |
| `e2e mcp` | Uses stdio and the same action authorization as a test run. A secret value never leaves the server: every output shows it as its marker. |
| `e2e explore` | Offers every configured credential to every step. The explorer sees account names and usernames. Passwords stay handles and are filled by secret. |
| `e2e explore --changed-since` | Sends the commit messages, the changed files' names, and the committed patches since the base to the model, cut to fit its context. A file no commit changed, such as one CI wrote, and a committed file's later local edits go by name only, never read. Secret values the config gives as strings, and runs of 8 or more of their characters, are redacted. A secret provider's value, and a secret committed to the repository that the config doesn't name, reach the model. |

## Navigation

Navigation is `POLICY_DENIED` for any scheme but `http:` and `https:`, other than the exact `about:blank`. `data:`, `javascript:`, and wrappers such as `view-source:file:` would load local or inline content, so the rule is an allowlist.

A target whose `app.url` is a `file:` URL has two more rules, because the agent names navigation URLs and a page can tell it to. Without them it could open any file you can read and carry it to an http(s) address.

- Navigation takes a `file:` URL only for a file in the directory of the app's file or below it, with symbolic links resolved. A file outside it and any directory are `POLICY_DENIED`: a directory listing links to its parent. A path that starts with `/` is the disk's root, so write it relative.
- A link or a script in a local page can still take the browser to a file outside the directory, where a typed URL cannot. Once it has, no model observation, trace screen, or failure screen text is taken: the observation is `POLICY_DENIED` (`a file app stays in the directory of the app's file`), and the trace and the failure evidence keep only where the page was. Your test's own reads (`Locator.TextContentAsync`, `Screen.TreeAsync`, `App.ScreenshotAsync`) still work, as test code is trusted.
- No screenshot of a file app is sent to a model or kept on its own. `Agent.AssertAsync` and a failure keep none, `Vision = VisionMode.On` judges from the tree, and `VisionMode.Only` is `POLICY_DENIED`. A local page can embed another file in a frame, which the tree leaves out and pixels would show.
- A video you turn on records the browser wherever it goes, a file outside the directory included.
- The directory of the app's file is the whole readable scope. In a project root that includes `.env` and `.git`: keep the file in a folder that holds only the app.

## Tool calls

- Built-in tools have closed schemas and appear only when the engine supports them. A tool that declares fields rejects a key it does not declare. A tool with no fields (`observe`, `back`, `dismiss_keyboard`, `screenshot`) drops extra keys and runs; a value that is not an object still fails.
- A project tool keeps the schema given to it, so whether it strips or rejects an undeclared key is up to that schema.
- A call to a tool the step doesn't offer, or with an undeclared argument on a built-in tool that declares fields, never runs. The model reads the refusal as the call's result and tries again.
- Over `e2e mcp`, `back` and `dismiss_keyboard` take no arguments: they drop any they are given and run. `observe` stays strict.
