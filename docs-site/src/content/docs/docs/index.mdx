Agentic end-to-end tests for .NET. Describe a goal in plain language, let an agent drive the app in Chromium, then check the result with locators. A verified agent step is recorded and replays on the next run with no model call.

```bash
dotnet add package E2E
dotnet add package E2E.NUnit   # or E2E.XUnit.V3 for xUnit v3
```

## Exit code of an interrupted run

`run.exitCode` in `report.json` is 130, and `run.status` is `interrupted`, once any test of the run was cancelled by the user, as upstream's runner reads its interrupt flag. This holds when the cancelled attempt was a retry: that test keeps its `failed` (or `timed-out`) verdict, since the failure came first, and the run still exits 130. A test that times out is not an interrupt. The flag is set only for an attempt that ends as an `OperationCanceledException` while the runner's token is cancelled (as `E2ESession.Complete` is called with it); the xUnit and NUnit adapters pass a cancelled test's cancellation on as such.

## Reporters

A reporter runs once, when the test run is over and `report.json` is final (upstream's `Reporter.onRunFinished`). Derive from `E2E.Reports.Reporter`, override `OnRunFinishedAsync`, and register the type for the test assembly:

```csharp
using E2E.Reports;

[assembly: E2EReporter(typeof(UploadReporter))]

public sealed class UploadReporter : Reporter
{
    public override string Name => "upload";

    public override async Task<IReadOnlyList<ReporterSummaryRow>?> OnRunFinishedAsync(FinishedRun run, CancellationToken cancellationToken)
    {
        // run.Report is the report-1 document, as written to run.ReportPath.
        return [new ReporterSummaryRow("Results", "https://example.test/runs/1")];
    }
}
```

The run ends when the run fixture is torn down (`E2ERunFixture`, see the setup reference), so add it: without it no reporter is called. The reporter needs a public constructor with no parameters. It is awaited for one minute, and the token is cancelled when that runs out. The rows it returns print to standard output after the tests. A reporter can never change the outcome: a throw or a timeout is one line on standard error. `OnEvent`, `FinishedRun.Traces`, `AiTracePath`, and `LastRun` are not ported.

## Filtering a locator

`Locator.Filter` keeps or drops the matches of a locator by their subtree. It takes any of four named arguments, and at least one.

```csharp
var row = Screen.GetByRole("listitem").Filter(hasText: "Invoice 42", hasNotText: "Paid");
await row.GetByRole("button", "Void").TapAsync();
```

- `hasText` with a string is a case-insensitive substring match over the match and its descendants, unlike a query text, which matches exactly. Pass a `Regex` for anything stricter.
- `hasNotText` excludes matches with that subtree text, using the same substring or `Regex` rules.
- `has` keeps a match whose subtree resolves the inner locator.
- `hasNot` drops a match whose subtree resolves the inner locator. It follows the same scoping rules as `has`.

`Filter()` with none of the four throws `INVALID_LOCATOR`, and so does a `has` or `hasNot` locator made by another screen. `Filter("text")` and `Filter(locator)` remain as the one-argument forms of `hasText` and `has`. On iOS, a plain React Native `View` has no children in the tree, so `has` on it matches nothing and `hasNot` keeps every such row.

## Scrolling to a node

A locator also takes `SecondaryTapAsync` (a right click), `LongPressAsync`, `HoverAsync`, `DragToAsync(target)`, and `SwipeAsync`. `TapAsync`, `DoubleTapAsync`, and `SecondaryTapAsync` hold keys for the click with `new ClickOptions { Modifiers = [KeyModifier.Shift] }` on the web engine; the others refuse them with `UNSUPPORTED_CAPABILITY`.

`Screen.ScrollUntilVisibleAsync(target, options)` scrolls the viewport until `target` resolves visibly. `Locator.ScrollUntilVisibleAsync(target, options)` swipes that node instead, so a feed or table that is its own scroll container pages without the pointer hovering it first.

```csharp
await Screen.ScrollUntilVisibleAsync(Screen.GetByRole("button", "Accept"));
await Screen.GetByTestId("feed").ScrollUntilVisibleAsync(row, new ScrollUntilVisibleOptions { Momentum = Momentum.Fast });
```

| Option | Type | Default |
| --- | --- | --- |
| `Direction` | `ScrollDirection` | `Down` |
| `Momentum` | `Momentum` (`None`, `Slow`, `Fast`) | `Slow` |
| `Timeout` | `TimeSpan` | 30 seconds |

`Timeout` is its own default, not `actionTimeout`, and bounds the whole scroll, each swipe included. `LOCATOR_NOT_FOUND` means the deadline expired first, a swipe it cut short included. `INVALID_LOCATOR` means `target` was made by another target's screen.

## Errors

A locator reports an engine failure in the test's own codes, with the engine's error as `InnerException`: `NOT_ACTIONABLE`, `ACTION_MAY_HAVE_COMMITTED`, and `OPERATION_TIMEOUT` are `ACTION_FAILED`, a stale node or a missing frame is `LOCATOR_NOT_FOUND`, an ambiguous frame is `LOCATOR_AMBIGUOUS`, and `INVALID_STATE` is `APP_NOT_OPEN`. `CANCELLED` and `ENGINE_FAILURE` keep their codes (category `infrastructure`), and `UNSUPPORTED_CAPABILITY` is a `ConfigurationException`. A stale node found by an action is looked up again, within the action timeout, before the action fails.

A read or navigation that times out fails with `OPERATION_TIMEOUT`. It is not retried, even when the call log mentions a detached element or a navigation race. On a device, an input (a tap, key, swipe, or `Back`) that the device does not answer within `actionTimeout` fails with `ACTION_MAY_HAVE_COMMITTED` and is never repeated, because it may have landed; an input the timeout ran out before is not sent (`OPERATION_TIMEOUT`), and a long press that holds at least as long as the time left is refused (`NOT_ACTIONABLE`). A locate, an observation, or a screenshot on a device runs within the timeout of the call that takes it, so a device that stops answering fails the step with `ACTION_FAILED` instead of holding it until the test timeout. `WaitForAsync`, `Expect`, and `ToHaveScreenshotAsync` give their last read extra time, up to their slowest read so far and within the test timeout, so a screen that shows up during it still passes. See `EngineErrorCodes` in the [API reference](/api/).
