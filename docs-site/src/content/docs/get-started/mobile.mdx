`MobileEngine` drives an iOS simulator or an Android emulator through [agent-device](https://github.com/callstack/agent-device). The tests use the same `Agent`, `Screen`, and `Expect` as web tests. For a .NET MAUI app, see [.NET MAUI](/get-started/maui/).

## Prerequisites

- macOS with Xcode and an iOS simulator runtime, or the Android SDK with an emulator.
- Node 22.12 or newer. `MobileEngine` starts agent-device through `npx`.
- Check the setup once: `npx --yes agent-device@0.21.35 doctor`.
- An app build: an `.app` bundle for the simulator, or an `.apk`.

## 1. Create the test project

```bash
dotnet new nunit -n MyApp.MobileTests
cd MyApp.MobileTests
dotnet add package E2E.Mobile.NUnit      # or E2E.Mobile.XUnit.V3
```

## 2. Point at your app

```json
{
  "targets": [
    {
      "name": "ios",
      "platform": "ios",
      "app": {
        "bundleId": "com.example.myapp",
        "appPath": "../MyApp/build/MyApp.app"
      }
    }
  ],
  "actionTimeout": 15000,
  "assertionTimeout": 10000,
  "agents": {
    "default": {
      "provider": "copilot",
      "model": "claude-sonnet-5.5",
      "context": "MyApp is a small demo app with a greeting form and a counter."
    }
  },
  "cache": { "dir": ".e2e/cache" }
}
```

`appPath` is relative to the folder of `e2e.config.json`. A device target has no URL. For Android, set `"platform": "android"` and `appPath` to the `.apk`, or run with `E2E_MOBILE_PLATFORM=android` and `E2E_MOBILE_APP_PATH`.

## 3. Write a test

Derive from `MobileAppTest`. It builds a `MobileEngine` from the config, installs the build once per run, launches the app fresh before each test, and gives the agent the `open_app`, `swipe`, and `alert` tools. `open_app` without an app returns to the target's app (`App.BundleId`), so the agent can recover after a system sheet or another app takes the foreground.

```csharp
using E2E.Mobile.NUnit;

public sealed class GreetingTests : MobileAppTest
{
    [Test]
    public async Task Greets_the_name_you_type()
    {
        await Screen.GetByTestId("name").FillAsync("Ada");
        await Screen.GetByTestId("greet").TapAsync();

        await Expect.That(Screen.GetByTestId("greeting")).ToHaveTextAsync("Hello, Ada!");
    }

    [Test]
    public async Task The_agent_gets_a_greeting()
    {
        await Agent.ActAsync("get the app to greet {name}", new ActOptions
        {
            Params = new Dictionary<string, object?> { ["name"] = "Grace" },
        });

        await Expect.That(Screen.GetByTestId("greeting")).ToHaveTextAsync("Hello, Grace!");
    }
}
```

`GetByTestId` finds a control by its accessibility identifier. A field's hint is its `Placeholder`, shown or not, so `GetByPlaceholder` finds it. Compose Multiplatform reports no placeholder on iOS: an empty field appends the text it draws to its label (`Name, Ada Lovelace`) over one `StaticText` child. For an empty (no value), editable, non-secure iOS field that reports no placeholder of its own, whose only child is a `StaticText` with no children, and whose label is a non-empty name, then `, `, then that child's text (`Name, Ada Lovelace`), that text is the field's `Placeholder`, the child is left out of the tree, and the name is the label before `, ` (a non-empty `ContentDescription` stays the name, and that label is then the `Text`). A field of any other shape keeps its label and children as reported. So `GetByPlaceholder("Ada Lovelace")` finds such a field and `GetByText("Ada Lovelace")` does not. `Device` is the device fixture: `HomeAsync`, `OpenAppAsync`, `ForegroundAppAsync`, and `SetAppearanceAsync(Appearance.Dark)`.

```csharp
await Device.HomeAsync();
await Device.OpenAppAsync(AppId, new OpenAppOptions { Relaunch = true });
```

`Device.Locator` takes an agent-device selector, for controls the `Screen` queries cannot name. It polls and is strict like any locator:

```csharp
await Expect.That(Device.Locator("role=navigation-bar id=About")).ToBeVisibleAsync();
await Device.Locator("id=SW_VERSION_SPECIFIER role=button").TapAsync();
```

Every action on a node pins its ref to the capture that issued it, so a ref a newer capture replaced is never sent to a different element. If the control changed during the `TransitionMilliseconds` wait (500 ms by default), the action fails with a retryable `NODE_STALE` and a locator resolves it again within its timeout. A direct `Device` call such as `DragToAsync` does not retry, so it surfaces the `NODE_STALE`.

For anything `Device` does not cover, `Device.UnstableRaw` has an [agent-device](https://github.com/callstack/agent-device) client bound to the test's session, plus the session name and the device's id and name. It is unstable and may change or go away in any release:

```csharp
var raw = Device.UnstableRaw;
var sessions = await raw.Client.CallAsync("sessions.list", null, CancellationToken.None);
await raw.Client.CallAsync("apps.list", raw.Selection.ToArgs(), CancellationToken.None);
```

`raw.Selection` is the device selection the engine passes commands (`ToArgs()` turns it into call options), for a call that can run before `app.open()`. `raw.Platform`, `raw.Session` (`e2e-<target>-<worker slot>`, or `<session>-<worker slot>` with the `Session` option), `raw.DeviceId` (a simulator UDID or an Android serial), and `raw.DeviceName` name the session and device. Client calls aren't steps: the report and trace leave them out, the agent cache doesn't replay them, secrets passed to them aren't redacted, and nothing waits for the screen to settle after one. After the worker disposes the session, reading `UnstableRaw` or its `Client` throws `INVALID_STATE`.

## 4. Run

Boot exactly one simulator, then run:

```bash
xcrun simctl boot "iPhone 17"
dotnet test --project .
```

To pick a device, set `E2E_MOBILE_DEVICE` to a UDID (`xcrun simctl list devices available`). With two booted or matching devices the run fails with `AMBIGUOUS_MATCH`.

Without `MobileOptions.Device`, a booted simulator or emulator that another tool holds through its own agent-device session is skipped, and the run drives the free ones. When every booted device is held, the run fails at `prepare` with `ENGINE_FAILURE`, naming the holding sessions. A booted device nothing holds, such as one you are using by hand, is still in the pool: name the device to keep the run off it.

Tag device tests, for example `[assembly: Category("Device")]`, so a machine without a device can skip them.

## Hosted devices

Set `E2E_MOBILE_PROVIDER=limrun` with `LIMRUN_API_KEY` to run on a hosted Limrun simulator. `E2E.Eas` and `E2E.TestMu.Mobile` add other providers. A provider whose service records its devices records the video of an attempt in place of agent-device (`IDeviceProvider.RecordAsync`). See the [mobile sample README](https://github.com/hardkoded/e2e-dotnet/tree/main/samples/MobileApp.E2ETests) for the full variable list.
