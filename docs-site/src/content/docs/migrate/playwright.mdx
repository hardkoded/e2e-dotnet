This guide ports upstream's `docs/migrate/playwright.mdx` (tester-army/e2e at `7b1b8b27`, with `a60310f9`, tester-army/e2e#1508, and `0852e61`, tester-army/e2e#1545). Upstream maps Node Playwright. This guide maps Playwright for .NET (`Microsoft.Playwright.NUnit`, `Microsoft.Playwright.Xunit`, or `Microsoft.Playwright`) and keeps upstream's order. Playwright .NET has no `playwright.config.ts`, so the config tables map `BrowserNewContextOptions`, the runner settings, and `.runsettings` instead.

`E2E` drives Chromium through `Microsoft.Playwright`, so both suites can share one browser install. The e2e tests live in their own test project, so `dotnet test` on the solution runs both suites and neither collects the other's tests.

## Agent prompt

```text
Migrate this project's Playwright .NET tests to e2e, one test class at a time. Docs: the "From Playwright .NET" page of the e2e-dotnet docs site (docs-site/src/content/docs/migrate/playwright.mdx).

1. Read the migration guide. It maps every Playwright .NET context option, Page call, and test attribute to e2e and marks what e2e does not have yet.
2. If the solution has no e2e test project, run `e2e init <directory> --yes` beside the Playwright project (add `--framework xunit` for xUnit v3). It creates the test project and example test, writes e2e.config.json, and installs the skill. In an existing test project it adds the missing package references to the .csproj.
3. Read the e2e skill (`e2e guide` prints it, `e2e guide <topic>` prints a topic) and follow it for every step below.
4. If you ran init, ask me which model to use for agent steps: a ChatGPT, GitHub Copilot, OpenCode Console, or SuperGrok subscription, an API key, or a local model. If it needs a sign-in, give me the `e2e login <provider>` command and wait until I confirm.
5. Port the context options and the base URL into e2e.config.json and the WebEngineOptions with the guide's config tables. Keep Microsoft.Playwright installed in the old project.
6. List the Playwright test classes and ask me which one to move first. Suggest a flow whose steps change often, such as a wizard or a checkout.
7. Rewrite that class with the same framework (NUnit or xUnit v3), deriving from E2ETest. Map each Page call to Screen, App, or Browser with the guide. Where a Playwright query matched a fragment, add exact: false or a Regex. Where the guide marks a feature missing, use the workaround it gives, or leave that test in Playwright and tell me why.
8. Keep navigation and the final assertions deterministic, with App.OpenAsync and Expect.That. Where a run of scripted interactions breaks often, propose an Agent.ActAsync goal for it instead.
9. Run the new class with `dotnet test --filter "FullyQualifiedName~<Class>"` and fix it until it passes. Keep the Playwright test until I confirm it can go.
10. Summarize which tests moved, which stayed in Playwright, and why.
```

For a migration that spans several sessions, the `migrate-to-e2e` skill records what moved in a progress file and keeps the old suite running until you retire each test. See [Coding agents](/coding-agents/#migrate-an-existing-suite).

## Port the config

Install e2e and configure a model with the [web guide](/get-started/web/).

Playwright .NET has no config file: a test class overrides `ContextOptions()`, and the runner reads `.runsettings` and environment variables. e2e reads `e2e.config.json` and a `WebEngineOptions` for the engine. The `setup` topic of the e2e skill lists every key.

### App, targets, and output

| Playwright .NET | e2e | Status |
| --- | --- | --- |
| `ContextOptions().BaseURL` | `app.url` on the target, or an override of `BaseUrl` on the test class | renamed |
| a web server you start yourself or from a `[OneTimeSetUp]` | `app: { url, command }` on the target; targets that declare the same command share one process | renamed |
| a `[OneTimeSetUp]` or `SetUpFixture` that seeds data | the framework's setup, a `[E2ESetup]` test for sign-in | same |
| the `BROWSER` environment variable, `Playwright.BrowserName` in `.runsettings` | `WebEngineOptions.BrowserName`: `BrowserName.Chromium`, `Firefox`, or `Webkit`. Two browsers on one app are two targets | renamed |
| `ExpectTimeout` in `.runsettings`, `Expect.SetDefaultExpectTimeout` | `assertionTimeout` in the config, or the `AssertionTimeout` override | renamed |
| `Page.SetDefaultTimeout` | `actionTimeout` in the config, or the `ActionTimeout` override | renamed |
| `Page.SetDefaultNavigationTimeout` | `timeout`, the test budget; `Browser.GotoAsync(url, new GotoOptions { Timeout })` overrides one call | renamed |
| NUnit's `[Timeout]`, `Retry`, `NumberOfTestWorkers` | the same attributes and settings: the framework owns them, and the config `retries` key is checked and not used. See [defaults that differ](#defaults-that-differ) | by design |
| the HTML report, `playwright.ps1 show-report` | `report.json` and `.e2e/results/<result>/trace.md` | missing |
| the `OutputDir` of a `PageTest` | `.e2e`, holding `results/` and the replay cache `cache/` | renamed |

## Rewrite one test

Start with a flow whose steps change often, such as a wizard or a checkout. Stable Playwright tests can stay where they are.

```csharp title="Playwright .NET (NUnit)"
using Microsoft.Playwright;
using Microsoft.Playwright.NUnit;

public class CheckoutTests : PageTest
{
    [Test]
    public async Task Checkout()
    {
        await Page.GotoAsync("/cart");
        await Page.GetByRole(AriaRole.Button, new() { Name = "Checkout" }).ClickAsync();
        await Page.GetByLabel("Card number").FillAsync("4242424242424242");
        await Page.GetByLabel("Expiry").FillAsync("12/30");
        await Page.GetByLabel("CVC").FillAsync("123");
        await Page.GetByRole(AriaRole.Button, new() { Name = "Pay" }).ClickAsync();
        await Expect(Page.GetByRole(AriaRole.Heading)).ToHaveTextAsync("Order confirmed");
    }
}
```

```csharp title="e2e (NUnit)"
using E2E.NUnit;

public sealed class CheckoutTests : E2ETest
{
    [Test]
    public async Task Checkout()
    {
        await App.OpenAsync("/cart");
        await Agent.ActAsync("pay with the test card 4242 4242 4242 4242, expiry 12/30, CVC 123");
        await Expect.That(Screen.GetByRole("heading")).ToHaveTextAsync("Order confirmed");
    }
}
```

```csharp title="e2e (xUnit v3)"
using E2E.XUnit.V3;

public sealed class CheckoutTests : E2ETest
{
    [Fact]
    public async Task Checkout()
    {
        await App.OpenAsync("/cart");
        await Agent.ActAsync("pay with the test card 4242 4242 4242 4242, expiry 12/30, CVC 123");
        await Expect.That(Screen.GetByRole("heading")).ToHaveTextAsync("Order confirmed");
    }
}
```

The agent does the checkout steps and adapts when the form changes. A test can also stay fully deterministic, with a `Screen.GetBy*` line for every `Page.GetBy*` line. Tag a test that calls a model with `[Category("RealModel")]` (NUnit) or `[Trait("TestCategory", "RealModel")]` (xUnit), so CI can skip it.

## Map each API

`Status` is `same`, `renamed`, `web only`, `by design`, or `missing` with what to do today. See [What differs on purpose](#what-differs-on-purpose) for the `by design` rows. Calls on `Browser` run only in a browser, so a device or document target fails them with `UNSUPPORTED_CAPABILITY`. Calls on `Screen`, `App`, `Agent`, and `Expect.That(locator)` run on every target.

### Locators

| Playwright .NET | e2e | Status |
| --- | --- | --- |
| `Page.GetByRole(AriaRole.Button, new() { Name = "Save" })` | `Screen.GetByRole("button", "Save")`; the role is a string and the name is positional | renamed |
| `GetByLabel`, `GetByText`, `GetByPlaceholder`, `GetByTestId` | the same on `Screen` | same |
| `GetByRole`, `GetByLabel`, `GetByPlaceholder`, `GetByText` with a string | an exact, case-sensitive match, see [What differs on purpose](#what-differs-on-purpose) | by design |
| `GetByRole(AriaRole.Img)` | the same; `img` is an alias of `image` | same |
| `GetByAltText(alt)` | `GetByRole("image", alt)` | renamed |
| `GetByTitle` | the node carries no title | missing |
| `GetByRole(role, new() { IncludeHidden = true })` | a role query never matches a hidden node; `Visible = true` on the other queries drops hidden twins | by design |
| `Filter(new() { HasText, HasNotText, Has, HasNot })`, `First`, `Last`, `Nth(i)`, `CountAsync()` | `Filter(hasText:, hasNotText:, has:, hasNot:)`, `First()`, `Last()`, `Nth(i)`, `CountAsync()` | same |
| `Locator.Or(other)` | the same; a locator is strict, so add `First()` when both match | same |
| `Locator.And(other)` | not yet | missing |
| `AllAsync()`, `AllTextContentsAsync()` | the same; `AllInnerTextsAsync()` is `AllTextContentsAsync()` | same |
| `Page.Locator("css")`, `Page.Locator("xpath=...")` | `Browser.Locator("css")`: the string is a Playwright selector, so `xpath=` (or a leading `//`) and `>>` chains work too | web only |
| `Page.WaitForSelectorAsync(selector)` | `Browser.Locator(selector).WaitForAsync()`; a locator is strict | renamed |
| `Page.ClickAsync(selector)`, `FillAsync(selector, value)`, `GetAttributeAsync(selector, name)`, and the other `Page` methods that take a selector | `Browser.Locator(selector).TapAsync()`, `.FillAsync(value)`, `.GetAttributeAsync(name)`. Playwright acts on the first match; a locator is strict, so add `First()` for the old behavior | renamed |
| `Locator.Locator("css")` | a semantic query inside the scope (`cell.GetByRole("textbox")` for `cell.Locator("input")`), `Browser.Locator("css").GetByRole(...)` the other way round, or one `Browser.Locator` selector for the whole path | missing |
| `Page.FrameLocator("#frame")` | `Browser.FrameLocator("#frame")`, then `Screen` queries inside it. A plain query never enters an iframe, as in Playwright | web only |

### Network and browser

| Playwright .NET | e2e | Status |
| --- | --- | --- |
| `Page.RouteAsync(pattern, handler)` | `Browser.RouteAsync(pattern, handler)`; a string or `Regex` pattern, no predicate function; the handler decides exactly once. A string is a glob on the full URL, never resolved against `app.url`. `?` matches any one character, where Playwright reads it literally; `{a,b}` is literal | web only |
| `route.FulfillAsync(new() { Json, Body, Path, Status, Headers, ContentType })` | `route.FulfillAsync(new RouteFulfillResponse { ... })`; one of `Json`, `Body`, or `Path`, and `Path` is relative to the project root. `Body` is text and bytes are `BodyBytes`; a `\n`-joined `set-cookie` sets each cookie | web only |
| `route.ContinueAsync(new() { Url, Method, Headers, PostData })`, `route.FallbackAsync()` | `ContinueAsync(new RouteContinueOverrides { ... })`, `FallbackAsync()`; a `Url` resolves against `app.url` and keeps the request's `http` or `https` scheme. A header Playwright sets to `undefined` is named in `DropHeaders` | web only |
| `route.FetchAsync()` | argument-free: no options, and redirects return unfollowed; returns `{ Url, Status, Headers, BodyAsync(), TextAsync(), JsonAsync<T>() }` without deciding the route | web only |
| `route.AbortAsync(errorCode)` | `AbortAsync()` takes no error code | missing |
| `Page.UnrouteAsync()` | `Browser.UnrouteAsync(pattern)` | web only |
| `Page.UnrouteAllAsync()` | `Browser.UnrouteAllAsync()`; configured headers stay | web only |
| `Page.WaitForResponseAsync(pattern)`, `RunAndWaitForResponseAsync` | `Browser.WaitForResponseAsync(pattern)`: a string or `Regex`, no predicate; `Url`, `Status`, `Headers`, `BodyAsync()`, `JsonAsync<T>()`, `TextAsync()`. Start it before the step that sends the request, and await it after | web only |
| a `Timeout` of `0` for no timeout | the same: `TimeSpan.Zero` sets no deadline of its own on a locator action, `WaitForAsync`, a matcher, `ToHaveScreenshotAsync`, `Browser.GotoAsync`, `WaitForResponseAsync`, `WaitForDownloadAsync`, and `WaitForDownloadsAsync`; the test timeout still bounds it. ## Port page objects

A page object takes `Screen` for queries and actions, and `Browser` for keyboard, mouse, CSS selectors, and `EvaluateAsync`. A page object's constructor takes the fixture members it needs, so a test builds it in a `[SetUp]` (NUnit) or in `InitializeAsync` (xUnit v3). Neither framework has a fixture-injection layer of e2e's own.

```csharp title="AccountPage.cs"
public sealed class AccountPage(Screen screen, Browser browser)
{
    public Locator AccountName { get; } = screen.GetByTestId("account-name");

    public async Task FilterByNoteAsync(string note)
    {
        await screen.GetByRole("button", "Filter").TapAsync();
        await screen.GetByRole("button", "Note").TapAsync();
        await browser.Keyboard.TypeAsync(note);
    }
}
```

```csharp title="AccountTests.cs (NUnit)"
public sealed class AccountTests : E2ETest
{
    private AccountPage _account = null!;

    [SetUp]
    public void CreatePages() => _account = new AccountPage(Screen, Browser);

    [Test]
    public async Task Filters_by_note()
    {
        await App.OpenAsync("/account");
        await _account.FilterByNoteAsync("rent");
        await Expect.That(_account.AccountName).ToBeVisibleAsync();
    }
}
```

A page object that reads `Browser` makes every test that uses it web only. `ILocator.Page` has no counterpart, so pass `Browser` with the locator. Drop `Context.NewPageAsync()` and `Page.CloseAsync()` from the hooks: every test starts in a fresh context.

## What differs on purpose

- A string name is exact. Playwright's `GetByRole` names, `GetByLabel`, `GetByPlaceholder`, and `GetByText` match a case-insensitive substring, so `Save` also hits `Save as draft`. In e2e a string matches the whole text, case-sensitive. Pass `exact: false` or a .NET `Regex` for a fragment (on the web it runs in the page as a JavaScript regular expression, tested against the raw text, as Playwright's does), and drop Playwright's `Exact = true`, which is the default here. A query that misses passes a negated assertion, so check it with a positive one first.

  ```csharp
  // <button>Save changes</button>, <label>Email address <input></label>
  Screen.GetByRole("button", "Save");                       // no match
  Screen.GetByRole("button", "Save", exact: false);         // matches
  Screen.GetByRole("button", "save changes");               // no match, case differs
  Screen.GetByLabel("Email");                               // no match
  ```
- Text reads are rendered text. On the web, `TextContentAsync()` and `ToHaveTextAsync` read what `innerText` returns, like Playwright's `UseInnerText = true`. Playwright reads the DOM's `textContent` by default. Queries still match the source text: `GetByText("Draft")` finds `<span style="text-transform: uppercase">Draft</span>`, and `ToHaveTextAsync("DRAFT")` passes on it. `Browser.EvaluateAsync` reads the raw DOM text.
- `.Not.ToBeCheckedAsync()` passes on a button or a heading, where Playwright throws, as `IsCheckedAsync()` does. Query a checkable control by role, so the query fails when the control changes kind.
- A negated locator matcher passes only after its condition has been false for 1 s in a row, or for its whole timeout when that is shorter. The positive inverse, such as `ToBeHiddenAsync()`, passes on the first read that holds.
- A `Browser` call that times out fails with `ACTION_FAILED`, and the message names the call: `operation timed out in browser.goto <url>` or `operation timed out in browser.waitForResponse "foo.css"`. An `App` call does the same (`operation timed out in app.open /orders`). Playwright's message, `Timeout 30000ms exceeded.`, is in the `InnerException`.
- `CheckAsync()` and `UncheckAsync()` read the state back until the action timeout, so a controlled checkbox that updates late passes. A click that removes the control passes too, where Playwright fails. Assert on what replaced it.
- One match or `LOCATOR_AMBIGUOUS`, `IsVisibleAsync()` included, where Playwright reads the first match silently. Narrow with `Filter`, `First()`, or `Visible = true`.
- Navigation opens `http`, `https`, and `about:blank` only. `data:`, `file:`, and every other scheme are `POLICY_DENIED`, whether from `App.OpenAsync`, `Browser.GotoAsync`, or a route's `ContinueAsync` `Url`.
- `Browser.EvaluateAsync<T>` takes and returns JSON only, so the report can record and redact the result. Pass values in through `arg`. A class instance, such as a `DOMRect` or an element, is `INVALID_ARGUMENT` instead of arriving as a partial object: return `rect.toJSON()` or the fields you need.
- A password is a `Secret` with no string value, and the model never sees it. See [Authentication](/features/signing-in/).
- Sessions are per run. A `[E2ESetup]` test saves state under a name, and `[E2ESession]` restores it. The file is encrypted, kept under `.e2e/sessions/<run id>`, and deleted at cleanup, so there is no `.auth/user.json` to reuse across runs.
- No raw `IPage` in tests. Nothing on a raw page is recorded, redacted, or masked.
