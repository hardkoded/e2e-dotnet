This guide ports upstream's `docs/migrate/playwright.mdx` (tester-army/e2e at `7b1b8b27`, with `a60310f9`, tester-army/e2e#1508, and `0852e61`, tester-army/e2e#1545). Upstream maps Node Playwright. This guide maps Playwright for .NET (`Microsoft.Playwright.NUnit`, `Microsoft.Playwright.Xunit`, or `Microsoft.Playwright`) and keeps upstream's order. Playwright .NET has no `playwright.config.ts`, so the config tables map `BrowserNewContextOptions`, the runner settings, and `.runsettings` instead.

`E2E` drives Chromium through `Microsoft.Playwright`, so both suites can share one browser install. The e2e tests live in their own test project, so `dotnet test` on the solution runs both suites and neither collects the other's tests.

## Agent prompt

```text
Migrate this project's Playwright .NET tests to e2e, one test class at a time. Docs: the "From Playwright .NET" page of the e2e-dotnet docs site (docs-site/src/content/docs/migrate/playwright.mdx).

1. Read the migration guide. It maps the Playwright .NET context options, Page calls, and test attributes that work in e2e, and lists what e2e doesn't have yet.
2. If the solution has no e2e test project, run `e2e init <directory> --yes` beside the Playwright project (add `--framework xunit` for xUnit v3). It creates the test project and example test, writes e2e.config.json, and installs the skill. In an existing test project it adds the missing package references to the .csproj.
3. Read the e2e skill (`e2e guide` prints it, `e2e guide <topic>` prints a topic) and follow it for every step below.
4. If you ran init, ask me which model to use for agent steps: a ChatGPT, GitHub Copilot, OpenCode Console, or SuperGrok subscription, an API key, or a local model. If it needs a sign-in, give me the `e2e login <provider>` command and wait until I confirm.
5. Port the context options and the base URL into e2e.config.json and the WebEngineOptions with the guide's config tables. Keep Microsoft.Playwright installed in the old project.
6. List the Playwright test classes and ask me which one to move first. Suggest a flow whose steps change often, such as a wizard or a checkout.
7. Check each Playwright .NET API in that class against "What e2e doesn't have yet". Use the "Use today" or "Use instead" entry, or leave that test in Playwright and tell me why. Then rewrite the class with the same framework (NUnit or xUnit v3), deriving from E2ETest. Map each Page call to Screen, App, or Browser with the guide. Where a Playwright query matched a fragment, add exact: false or a Regex.
8. Keep navigation and the final assertions deterministic, with App.OpenAsync and Expect.That. Where a run of scripted interactions breaks often, propose an Agent.ActAsync goal for it instead.
9. Run the new class with `dotnet test --filter "FullyQualifiedName~<Class>"` and fix it until it passes. Keep the Playwright test until I confirm it can go.
10. Summarize which tests moved, which stayed in Playwright, and why.
```

For a migration that spans several sessions, the `migrate-to-e2e` skill records what moved in a progress file and keeps the old suite running until you retire each test. See [Coding agents](/coding-agents/#migrate-an-existing-suite).

## Port the config

Install e2e and configure a model with the [web guide](/get-started/web/).

Playwright .NET has no config file: a test class overrides `ContextOptions()`, and the runner reads `.runsettings` and environment variables. e2e reads `e2e.config.json` and a `WebEngineOptions` for the engine. The `setup` topic of the e2e skill lists every key.

### App, targets, and output

| Playwright .NET | e2e |
| --- | --- |
| `ContextOptions().BaseURL` | `app.url` on the target, or an override of `BaseUrl` on the test class |
| a web server you start yourself or from a `[OneTimeSetUp]` | `app: { url, command }` on the target; targets that declare the same command share one process |
| a `[OneTimeSetUp]` or `SetUpFixture` that seeds data | the framework's setup, a `[E2ESetup]` test for sign-in |
| the `BROWSER` environment variable, `Playwright.BrowserName` in `.runsettings` | `WebEngineOptions.BrowserName`: `BrowserName.Chromium`, `Firefox`, or `Webkit`. Two browsers on one app are two targets |
| `ExpectTimeout` in `.runsettings`, `Expect.SetDefaultExpectTimeout` | `assertionTimeout` in the config, or the `AssertionTimeout` override |
| `Page.SetDefaultTimeout` | `actionTimeout` in the config, or the `ActionTimeout` override |
| `Page.SetDefaultNavigationTimeout` | `timeout`, the test budget; `Browser.GotoAsync(url, new GotoOptions { Timeout })` overrides one call |
| changing a running test's timeout from its body | `SetTimeout(TimeSpan)` on `E2ETest` (upstream's `test.setTimeout`), from the body or a set-up (`[SetUp]` on NUnit). It counts from the start of the attempt and replaces the configured `timeout` for that attempt. It is refused from a teardown, and there is no value for no timeout: pass a large one. Pass `[Timeout]` or the config `timeout` to set it ahead of time |
| NUnit's `[Timeout]`, `Retry`, `NumberOfTestWorkers` | the same attributes and settings: the framework owns them, and the config `retries` key is checked and not used. See [defaults that differ](#defaults-that-differ) |
| the `OutputDir` of a `PageTest` | `.e2e`, holding `results/` and the replay cache `cache/` |

| Playwright .NET | e2e |
| --- | --- |
| `ViewportSize` | `WebEngineOptions.Viewport`, default 1280 by 720 |
| `Playwright.Selectors.SetTestIdAttribute` | `WebEngineOptions.TestIdAttribute` |
| `HttpCredentials` | `WebEngineOptions.BasicAuth = new WebBasicAuth(username, secret)`, answered for the app's origin only; `CredentialOrigins` adds more |
| `ExtraHTTPHeaders` | `WebEngineOptions.Headers`, sent on requests that start at the app's origin; `CredentialOrigins` adds more |
| `BrowserType.ConnectOverCDPAsync(url)` | `WebEngineOptions.Connect = new WebConnectOptions { CdpEndpoint = ct => ... }`, Chromium only |
| `StorageState`, a setup test that saves it | `[E2ESetup("title", Saves = ["admin"])]` with `SaveSessionAsync("admin")`, then `[E2ESession("admin")]` on a test; no file |
| `StorageState` with fixed cookies | `Browser.SetCookiesAsync(cookies)` in a `[SetUp]` |
| `Tracing.StartAsync` and `StopAsync` | `trace`: `off`, `on`, `retain-on-failure`, `on-first-retry`, or `on-all-retries`, in the config, per target, or `E2E_TRACE`. A trace is a markdown page, `trace.md`, not a zip, with no viewer. No `retain-on-first-failure`, `retain-on-failure-and-retries`, or object form. The default differs, see [below](#defaults-that-differ) |
| `RecordVideoDir` | `video`, with the modes of `trace` and `E2E_VIDEO`; no `RecordVideoSize` |
| `Headless = false`, `HEADED=1` | `E2E_HEADLESS=0`, or `new WebEngineOptions { Headless = false }` |
| `Locale`, `TimezoneId` | `WebEngineOptions.Locale`, `TimezoneId` |
| `ColorScheme`, `ReducedMotion` | `WebEngineOptions.ColorScheme`, `ReducedMotion` |
| `UserAgent` | `WebEngineOptions.UserAgent` |
| `Permissions` | `app.permissions` on the target, `{ "clipboard-read": "grant" }`: `grant` only, held by every page on any origin. See [Granting browser permissions](/get-started/web/#granting-browser-permissions) in the web guide |

## Rewrite one test

Start with a flow whose steps change often, such as a wizard or a checkout. Stable Playwright tests can stay where they are.

```csharp title="Playwright .NET (NUnit)"
using Microsoft.Playwright;
using Microsoft.Playwright.NUnit;

public class CheckoutTests : PageTest
{
    [Test]
    public async Task Checkout()
    {
        await Page.GotoAsync("/cart");
        await Page.GetByRole(AriaRole.Button, new() { Name = "Checkout" }).ClickAsync();
        await Page.GetByLabel("Card number").FillAsync("4242424242424242");
        await Page.GetByLabel("Expiry").FillAsync("12/30");
        await Page.GetByLabel("CVC").FillAsync("123");
        await Page.GetByRole(AriaRole.Button, new() { Name = "Pay" }).ClickAsync();
        await Expect(Page.GetByRole(AriaRole.Heading)).ToHaveTextAsync("Order confirmed");
    }
}
```

```csharp title="e2e (NUnit)"
using E2E.NUnit;

public sealed class CheckoutTests : E2ETest
{
    [Test]
    public async Task Checkout()
    {
        await App.OpenAsync("/cart");
        await Agent.ActAsync("pay with the test card 4242 4242 4242 4242, expiry 12/30, CVC 123");
        await Expect.That(Screen.GetByRole("heading")).ToHaveTextAsync("Order confirmed");
    }
}
```

```csharp title="e2e (xUnit v3)"
using E2E.XUnit.V3;

public sealed class CheckoutTests : E2ETest
{
    [Fact]
    public async Task Checkout()
    {
        await App.OpenAsync("/cart");
        await Agent.ActAsync("pay with the test card 4242 4242 4242 4242, expiry 12/30, CVC 123");
        await Expect.That(Screen.GetByRole("heading")).ToHaveTextAsync("Order confirmed");
    }
}
```

The agent does the checkout steps and adapts when the form changes. A test can also stay fully deterministic, with a `Screen.GetBy*` line for every `Page.GetBy*` line. Tag a test that calls a model with `[Category("RealModel")]` (NUnit) or `[Trait("TestCategory", "RealModel")]` (xUnit), so CI can skip it.

## Map each API

Every row works today. For an API that is not here, check [What e2e doesn't have yet](#what-e2e-doesnt-have-yet). Calls on `Browser` run only in a browser, so a device or document target fails them with `UNSUPPORTED_CAPABILITY`. Calls on `Screen`, `App`, `Agent`, and `Expect.That(locator)` run on every target.

### Locators

| Playwright .NET | e2e |
| --- | --- |
| `Page.GetByRole(AriaRole.Button, new() { Name = "Save" })` | `Screen.GetByRole("button", "Save")`; the role is a string and the name is positional |
| `GetByLabel`, `GetByText`, `GetByPlaceholder`, `GetByTestId` | the same on `Screen` |
| `GetByRole`, `GetByLabel`, `GetByPlaceholder`, `GetByText` with a string | an exact, case-sensitive match, see [What differs on purpose](#what-differs-on-purpose) |
| `GetByRole(AriaRole.Img)` | the same; `img` is an alias of `image` |
| `GetByAltText(alt)` | `GetByRole("image", alt)` |
| `Filter(new() { HasText, HasNotText, Has, HasNot })`, `First`, `Last`, `Nth(i)`, `CountAsync()` | `Filter(hasText:, hasNotText:, has:, hasNot:)`, `First()`, `Last()`, `Nth(i)`, `CountAsync()` |
| `Locator.Or(other)` | the same; a locator is strict, so add `First()` when both match |
| `AllAsync()`, `AllTextContentsAsync()` | the same; `AllInnerTextsAsync()` is `AllTextContentsAsync()` |
| `Page.Locator("css")`, `Page.Locator("xpath=...")` | `Browser.Locator("css")`: the string is a Playwright selector, so `xpath=` (or a leading `//`) and `>>` chains work too |
| `Page.WaitForSelectorAsync(selector)` | `Browser.Locator(selector).WaitForAsync()`; a locator is strict |
| `Page.ClickAsync(selector)`, `FillAsync(selector, value)`, `GetAttributeAsync(selector, name)`, and the other `Page` methods that take a selector | `Browser.Locator(selector).TapAsync()`, `.FillAsync(value)`, `.GetAttributeAsync(name)`. Playwright acts on the first match; a locator is strict, so add `First()` for the old behavior |
| `Page.FrameLocator("#frame")` | `Browser.FrameLocator("#frame")`, then `Screen` queries inside it. A plain query never enters an iframe, as in Playwright |

### Actions

| Playwright .NET | e2e |
| --- | --- |
| `ClickAsync()` | `TapAsync()`; `ClickAsync()` is an alias |
| `ClickAsync(new() { Button = MouseButton.Right })` | `SecondaryTapAsync()` |
| `DblClickAsync()` | `DoubleTapAsync()`; `DblClickAsync()` is an alias |
| `ClickAsync(new() { ClickCount = 3 })` | `TapAsync(new TapOptions { Count = 3 })`; 2 is `DoubleTapAsync()`, and a `Count` above 1 does not combine with `Position` |
| `ClickAsync(new() { Position })` | `TapAsync(new TapOptions { Position })`, an offset from the node's top-left corner inside its border |
| `ClickAsync(new() { Modifiers })`, `DblClickAsync(new() { Modifiers })` | `TapAsync(new ClickOptions { Modifiers = [...] })`, `DoubleTapAsync`, `SecondaryTapAsync`; web only |
| `ClickAsync(new() { Delay })` | `LongPressAsync(new LongPressOptions { Duration })` |
| `FillAsync(value)` | the same; also takes a `Secret` |
| `PressSequentiallyAsync(text, new() { Delay })` | `PressSequentiallyAsync(text, new PressSequentiallyOptions { Delay })`; focuses the field, then types through the platform keyboard, one call for the whole text or one per code point with a `Delay`; the call shares one `Timeout` and fails with `ACTION_FAILED` when a pause reaches it; a `Secret` has no overload, so it goes through `FillAsync` |
| `PressAsync(key)` | the same; modifiers join with `+` |
| `ClearAsync()`, `FocusAsync()`, `BlurAsync()`, `HoverAsync()`, `SetInputFilesAsync()`, `DragToAsync()` | the same verbs, each with `Timeout` as the only option (`ActionOptions`): no `Force`, `Trial`, `Position`, `Modifiers`, or `SourcePosition`. `SetInputFilesAsync([])` clears the input |
| `SetInputFilesAsync(new FilePayload { Name, MimeType, Buffer })` | `SetInputFilesAsync(new FilePayload(name, mimeType, buffer))`. Web only. Pass one payload or a list of them, not mixed with paths. The combined size must be under 50 MiB |
| `CheckAsync()`, `UncheckAsync()` | the same, except when the state updates late or the click removes the control, see [What differs on purpose](#what-differs-on-purpose). `UncheckAsync()` on a checked native radio is `ACTION_FAILED` (`NOT_ACTIONABLE`); a `role=radio` is clicked, as in Playwright |
| `SelectOptionAsync("pro")` | `SelectOptionAsync("Pro")` selects the option whose value or label is the string |
| `ScrollIntoViewIfNeededAsync()` | `ScrollIntoViewAsync()` |
| `InnerTextAsync()` | `TextContentAsync()`, whitespace collapsed to single spaces |
| `TextContentAsync()` | the rendered text, what `InnerTextAsync()` reads, see [What differs on purpose](#what-differs-on-purpose) |
| `GetAttributeAsync()`, `IsVisibleAsync()`, `IsHiddenAsync()`, `IsEnabledAsync()`, `IsDisabledAsync()`, `IsCheckedAsync()`, `BoundingBoxAsync()` | the same |
| `InputValueAsync()` | the same, and reads a `contenteditable` editor, where Playwright throws. A checkbox or radio reads its value attribute, `on` when it has none |
| `WaitForAsync(new() { State = WaitForSelectorState.Visible })`, `Hidden`, `Attached`, `Detached` | `WaitForAsync` takes the same four states |
| `Page.Keyboard.PressAsync`, `Keyboard.TypeAsync` | `Browser.Keyboard.PressAsync`, `Browser.Keyboard.TypeAsync`; plain text only, never a `Secret` |
| `Keyboard.DownAsync`, `Keyboard.UpAsync` | `Browser.Keyboard.DownAsync`, `UpAsync`; keys and modifiers stay held until released |
| `Page.Mouse.ClickAsync(x, y)` | `Screen.TapAtAsync(new Point(x, y))`, viewport coordinates |
| `Page.Mouse.DblClickAsync(x, y)` | `Screen.DoubleTapAtAsync(new Point(x, y))`, viewport coordinates |
| `Mouse.MoveAsync`, `DownAsync`, `UpAsync`, `WheelAsync` | `Browser.Mouse.*` |
| `Page.DragAndDropAsync(source, target, new() { SourcePosition, TargetPosition })` | `source.DragToAsync(target)`, which takes no positions |

### Assertions

`Expect(locator)` of a `PageTest` becomes `Expect.That(locator)`. The matcher names are the same.

| Playwright .NET | e2e |
| --- | --- |
| `ToBeVisibleAsync`, `ToBeHiddenAsync`, `ToBeEnabledAsync`, `ToBeDisabledAsync`, `ToBeFocusedAsync`, `ToHaveValueAsync`, `ToHaveAttributeAsync`, `ToHaveCountAsync`, `ToHaveAccessibleNameAsync`, `ToHaveRoleAsync`, `ToBeEditableAsync` | the same |
| `ToBeInViewportAsync(new() { Ratio })` | `ToBeInViewportAsync(ratio)`; a zero-size element reads as outside, and on a device `ratio > 0` fails with `UNSUPPORTED_CAPABILITY` because a device reports only the visible part of a box |
| `ToBeCheckedAsync()` | the same on a checkable node; on any other node `.Not.ToBeCheckedAsync()` passes, see [What differs on purpose](#what-differs-on-purpose) |
| `ToHaveTextAsync()`, `ToContainTextAsync()` | compare the rendered text, see [What differs on purpose](#what-differs-on-purpose) |
| `ToHaveTextAsync(new[] { "a", "b" })` on several matches | the same: `ToHaveTextAsync` needs the count to match |
| `ToBeCheckedAsync(new() { Checked = false })`, `ToBeEnabledAsync(new() { Enabled })`, `ToBeEditableAsync(new() { Editable })`, `ToBeVisibleAsync(new() { Visible })` | `ToBeCheckedAsync(false)`, `ToBeEditableAsync(false)`; the others use `.Not` |
| `IgnoreCase` on `ToHaveTextAsync`, `ToContainTextAsync` | `ignoreCase:` on the same matchers |
| `ToHaveAttributeAsync("aria-selected", "true")`, `"aria-expanded"` | `ToBeSelectedAsync()`, `ToBeExpandedAsync()` |
| a positive matcher on several matches | `LOCATOR_AMBIGUOUS` at once, see [What differs on purpose](#what-differs-on-purpose) |
| `.Not.ToBeVisibleAsync()`, `.Not.ToBeCheckedAsync()`, `.Not.ToBeEnabledAsync()` | `ToBeHiddenAsync()`, `ToBeCheckedAsync(false)`, `ToBeDisabledAsync()`, which needs a match, so a control that is gone fails where `.Not.ToBeEnabledAsync()` passes in Playwright. A `.Not` locator matcher holds for up to 1 s before it passes, see [What differs on purpose](#what-differs-on-purpose) |
| `ToBeAttachedAsync()` | the same; passes on a hidden match too |
| `Expect(locator).ToHaveClassAsync(cls)` | `Expect.That(Browser).ToHaveClassAsync(locator, cls)`; a DOM fact is asserted through `Browser`; `class=""` matches an empty list and a missing attribute does not |
| `Expect(Page).ToHaveURLAsync()`, `ToHaveTitleAsync()` | `Expect.That(Browser).ToHaveURLAsync()`, `ToHaveTitleAsync()`; `ToHaveURLAsync` takes `ignoreCase` |
| `Expect(locator, new() { Message })`, `Expect(Page, new() { Message }).ToHaveScreenshotAsync()` | `Expect.That(locator, "message")`, `Expect.That(Screen, "message")` for the page; the message opens the failure, see [Soft assertions and evidence](/features/assertions/) |
| `Expect(Page).ToHaveScreenshotAsync()`, `Expect(locator).ToHaveScreenshotAsync()` | `Expect.That(Screen).ToHaveScreenshotAsync(name)`, `Expect.That(locator).ToHaveScreenshotAsync()`, web only, with `Threshold`, `MaxDiffPixels`, `MaxDiffPixelRatio`, `Mask`, `MaskColor`, and `Timeout`. Set `E2E_UPDATE_SNAPSHOTS=1` to rewrite |
| `Assert.That(value, ...)`, `Assert.AreEqual` | the framework's asserts, unchanged |
| `Expect(async () => { ... }).ToPassAsync()` | `Expect.That(async () => { ... }).ToPassAsync(new PassOptions { Timeout, Intervals })`. It retries a block until it stops throwing. The timeout defaults to `toPass.timeout` of the config, else only the test deadline applies. `Expect.Poll(read).ToBeAsync(...)` retries a read instead, with a 5 s `PollOptions.Timeout` |
| `Expect.Soft` | `Expect.Soft(locator)` and `Expect.Soft(screen)`; kept failures fail the test at its end |

### Navigation and app

| Playwright .NET | e2e |
| --- | --- |
| `Page.GotoAsync(path)` | `App.OpenAsync(path)`; `Browser.GotoAsync(url, new GotoOptions { WaitUntil, Timeout })` for the browser options |
| `Page.GoBackAsync()` | `App.BackAsync()`, or `Browser.BackAsync()` |
| `Page.GoForwardAsync()`, `Page.ReloadAsync()` | `Browser.ForwardAsync()`, `Browser.ReloadAsync()` |
| `Page.Url`, `Page.TitleAsync()` | `await Browser.UrlAsync()`, `await Browser.TitleAsync()` |
| `Page.WaitForURLAsync()` | `Browser.WaitForURLAsync()`. A string is an absolute URL, or a relative one resolved against `app.url`, matched exactly, not a glob: `"**/orders"` never matches, so pass a `Regex` |
| `Page.SetViewportSizeAsync()` | `Browser.SetViewportAsync()`, before or after the first navigation |
| `Page.ScreenshotAsync()` | `App.ScreenshotAsync(label)`: the viewport, redacted, attached to the report; no `FullPage` |
| a fresh `IBrowserContext` per test | every test starts in a fresh context; `App.RestartAsync()` recreates it, `App.ClearStateAsync()` also clears storage. No page opens before the first `App.OpenAsync` or `Browser.GotoAsync`, where Playwright starts on `about:blank` |

### Network and browser

| Playwright .NET | e2e |
| --- | --- |
| `Page.RouteAsync(pattern, handler)` | `Browser.RouteAsync(pattern, handler)`; a string or `Regex` pattern, or `new RouteMatcher { Method = "POST", Url = "**/api/orders" }` for one HTTP method, no predicate function; the handler decides exactly once. A string is a glob on the full URL, never resolved against `app.url`. `?` matches any one character, where Playwright reads it literally; `{a,b}` is literal |
| `route.FulfillAsync(new() { Json, Body, Path, Status, Headers, ContentType })` | `route.FulfillAsync(new RouteFulfillResponse { ... })`; one of `Json`, `Body`, or `Path`, and `Path` is relative to the project root. `Body` is text and bytes are `BodyBytes`; a `\n`-joined `set-cookie` sets each cookie |
| `route.ContinueAsync(new() { Url, Method, Headers, PostData })`, `route.FallbackAsync()` | `ContinueAsync(new RouteContinueOverrides { ... })`, `FallbackAsync()`; a `Url` resolves against `app.url` and keeps the request's `http` or `https` scheme. A header Playwright sets to `undefined` is named in `DropHeaders` |
| `route.FetchAsync()` | argument-free: no options, and redirects return unfollowed; returns `{ Url, Status, Headers, BodyAsync(), TextAsync(), JsonAsync<T>() }` without deciding the route |
| `Page.UnrouteAsync()` | `Browser.UnrouteAsync(pattern)`; it removes the routes registered with the same pattern, method included, rather than URL-matching them |
| `Page.UnrouteAllAsync()` | `Browser.UnrouteAllAsync()`; configured headers stay |
| `Page.WaitForResponseAsync(urlOrPredicate)`, `Page.WaitForRequestAsync(urlOrPredicate)`, `RunAndWaitForResponseAsync` | `Browser.WaitForResponseAsync` and `Browser.WaitForRequestAsync` with a glob string, `Regex`, `RouteMatcher` to filter on the request's method, or a predicate (`Func<PageResponse, bool>` or `Func<PageResponse, Task<bool>>`; `Func<WebRequest, ...>` for a request). A response has `Url`, `Status`, `Headers`, `Request`, `BodyAsync()`, `JsonAsync<T>()`, `TextAsync()`; `Url`, `Status`, `Headers`, and `Request` are properties, and only the body readers are methods. A `timeout` is the only option. A string is the glob of `Browser.RouteAsync`, tested against the whole URL, query included: Playwright's `"/api/orders"` is the full URL or `"**/api/orders"`, and `"\\?"` is a literal `?`. Start it before the step that sends the request, and await it after |
| a `Timeout` of `0` for no timeout | the same: `TimeSpan.Zero` sets no deadline of its own on a locator action, `WaitForAsync`, a matcher, `ToHaveScreenshotAsync`, `Browser.GotoAsync`, `WaitForResponseAsync`, `WaitForRequestAsync`, `WaitForPopupAsync`, `WaitForDownloadAsync`, and `WaitForDownloadsAsync`; the test timeout still bounds it. A negative `TimeSpan` throws `TestException` with `INVALID_ARGUMENT`. `Expect.Poll` with `Timeout = TimeSpan.Zero` polls until the cancellation token you pass ends, and without one it throws `ConfigurationException` with `INVALID_CONFIG` |
| `Page.Dialog += handler` | `await Browser.OnDialogAsync(DialogHandler.Accept)`, or a handler that calls `AcceptAsync` or `DismissAsync` |
| `Page.RunAndWaitForDownloadAsync(...)` | `Browser.WaitForDownloadAsync(() => trigger)`, and `WaitForDownloadsAsync(trigger, count)` for several files |
| `Page.WaitForPopupAsync()` | `Browser.WaitForPopupAsync(() => trigger)`, which also makes the tab active. Without it, a tab the app opens stays in the background, as in Playwright. When the active tab closes, its opener is active again, or the tab active most recently when the opener is gone |
| `Context.Page +=`, `Context.Pages`, `Context.NewPageAsync()`, `Page.BringToFrontAsync()` | `Browser.Tabs()`, `Browser.NewTabAsync()`, `BrowserTab.ActivateAsync()`; no event per new page |
| `Page.EvaluateAsync(fn, arg)` | `Browser.EvaluateAsync<T>(expression, arg)`; JSON in and out, no handles |
| `Page.AddInitScriptAsync(script)`, `Context.AddInitScriptAsync()` | `Browser.AddInitScriptAsync(source)`, or `WebEngineOptions.InitScripts` for every test |
| `Page.EmulateMediaAsync(new() { ColorScheme, ReducedMotion })` | `Browser.EmulateMediaAsync(new WebMedia { ... })`, for every open tab and every tab opened after it; `Media`, `ForcedColors`, and `Contrast` are not supported |
| `Context.AddCookiesAsync()`, `Context.CookiesAsync()` | `Browser.SetCookiesAsync()`, `Browser.CookiesAsync()` |
| `Context.ClearCookiesAsync(options)` | `Browser.ClearCookiesAsync(new CookieFilter { ... })` |

### Test structure

| Playwright .NET | e2e |
| --- | --- |
| `using Microsoft.Playwright.NUnit;` and `PageTest` | `using E2E.NUnit;` and `E2ETest`; for xUnit, `using E2E.XUnit.V3;` and its `E2ETest` |
| `[Test]`, `[TestFixture]`, `[SetUp]`, `[TearDown]` | the same NUnit attributes. Your `[SetUp]` runs after the base class's, so the session is ready there |
| `[OneTimeSetUp]`, `[OneTimeTearDown]` | the same, with no session: the session starts for each test |
| `Page` in a test | `Screen`, `App`, `Browser`; no raw `IPage` in tests, see [What differs on purpose](#what-differs-on-purpose) |
| `[Ignore]`, `Assert.Ignore` | the same |
| `[Explicit]`, `[Category("smoke")]` | the same NUnit attributes; for xUnit, `[Fact(Explicit = true)]` and `[Trait("TestCategory", "smoke")]` |
| `[Parallelizable(ParallelScope.Self)]` | a test class with `ParallelScope.Children` or `All` fails at setup unless it also has `[FixtureLifeCycle(LifeCycle.InstancePerTestCase)]`; xUnit runs classes in parallel |
| `test.describe.configure({ mode: 'serial' })` (members share a page) | `[Serial]` on an NUnit test class: its members share one session, in the order of `[DependsOnTest]`, and a failure skips the rest. xUnit has no counterpart |
| `[Retry(n)]` | the same on NUnit: the first attempt can replay the cache, and a retry runs every agent step live. xUnit has no retry attribute |
| `ContextOptions()` override | per target in the config, or `CreateEngine()` on the test class; `Browser.SetViewportAsync` at runtime |
| a base class with fixtures | the same: a class that derives from `E2ETest` and adds protected members or helper methods |
| `[SetUpFixture]` | the framework's own, with no session |

### Running tests

| Playwright .NET | e2e |

## Port page objects

A page object takes `Screen` for queries and actions, and `Browser` for keyboard, mouse, CSS selectors, and `EvaluateAsync`. A page object's constructor takes the fixture members it needs, so a test builds it in a `[SetUp]` (NUnit) or in `InitializeAsync` (xUnit v3). Neither framework has a fixture-injection layer of e2e's own.

```csharp title="AccountPage.cs"
public sealed class AccountPage(Screen screen, Browser browser)
{
    public Locator AccountName { get; } = screen.GetByTestId("account-name");

    public async Task FilterByNoteAsync(string note)
    {
        await screen.GetByRole("button", "Filter").TapAsync();
        await screen.GetByRole("button", "Note").TapAsync();
        await browser.Keyboard.TypeAsync(note);
    }
}
```

```csharp title="AccountTests.cs (NUnit)"
public sealed class AccountTests : E2ETest
{
    private AccountPage _account = null!;

    [SetUp]
    public void CreatePages() => _account = new AccountPage(Screen, Browser);

    [Test]
    public async Task Filters_by_note()
    {
        await App.OpenAsync("/account");
        await _account.FilterByNoteAsync("rent");
        await Expect.That(_account.AccountName).ToBeVisibleAsync();
    }
}
```

A page object that reads `Browser` makes every test that uses it web only. `ILocator.Page` has no counterpart, so pass `Browser` with the locator. Drop `Context.NewPageAsync()` and `Page.CloseAsync()` from the hooks: every test starts in a fresh context.

## What differs on purpose

- A string name is exact. Playwright's `GetByRole` names, `GetByLabel`, `GetByPlaceholder`, and `GetByText` match a case-insensitive substring, so `Save` also hits `Save as draft`. In e2e a string matches the whole text, case-sensitive. Pass `exact: false` or a .NET `Regex` for a fragment (on the web it runs in the page as a JavaScript regular expression, tested against the raw text, as Playwright's does), and drop Playwright's `Exact = true`, which is the default here. A query that misses passes a negated assertion, so check it with a positive one first.

  ```csharp
  // <button>Save changes</button>, <label>Email address <input></label>
  Screen.GetByRole("button", "Save");                       // no match
  Screen.GetByRole("button", "Save", exact: false);         // matches
  Screen.GetByRole("button", "save changes");               // no match, case differs
  Screen.GetByLabel("Email");                               // no match
  ```
- `ToHaveRoleAsync` takes the `GetByRole` vocabulary as a string, and `img` reads as `image`. It compares the role the tree reads, where a `contenteditable` editor is a `textbox`.
- Text reads are rendered text. On the web, `TextContentAsync()` and `ToHaveTextAsync` read what `innerText` returns, like Playwright's `UseInnerText = true`. Playwright reads the DOM's `textContent` by default. Queries still match the source text: `GetByText("Draft")` finds `<span style="text-transform: uppercase">Draft</span>`, and `ToHaveTextAsync("DRAFT")` passes on it. `Browser.EvaluateAsync` reads the raw DOM text.
- `.Not.ToBeCheckedAsync()` passes on a button or a heading, where Playwright throws, as `IsCheckedAsync()` does. Query a checkable control by role, so the query fails when the control changes kind.
- A negated locator matcher passes only after its condition has been false for 1 s in a row, or for its whole timeout when that is shorter. The positive inverse, such as `ToBeHiddenAsync()`, passes on the first read that holds.
- A `Browser` call that times out fails with `ACTION_FAILED`, and the message names the call: `operation timed out in browser.goto <url>` or `operation timed out in browser.waitForResponse "foo.css"`. An `App` call does the same (`operation timed out in app.open /orders`). Playwright's message, `Timeout 30000ms exceeded.`, is in the `InnerException`.
- `CheckAsync()` and `UncheckAsync()` read the state back until the action timeout, so a controlled checkbox that updates late passes. A click that removes the control passes too, where Playwright fails. Assert on what replaced it.
- One match or `LOCATOR_AMBIGUOUS`, `IsVisibleAsync()` included, where Playwright reads the first match silently. Narrow with `Filter`, `First()`, or `Visible = true`.
- Navigation opens `http`, `https`, and `about:blank` only. `data:`, `file:`, and every other scheme are `POLICY_DENIED` (a `file:` URL opens only on a target whose `app.url` is itself a file, for a file in that file's directory or below it), whether from `App.OpenAsync`, `Browser.GotoAsync`, or a route's `ContinueAsync` `Url`.
- `Browser.EvaluateAsync<T>` takes and returns JSON only, so the report can record and redact the result. Pass values in through `arg`. A class instance, such as a `DOMRect` or an element, is `INVALID_ARGUMENT` instead of arriving as a partial object: return `rect.toJSON()` or the fields you need.
- A password is a `Secret` with no string value, and the model never sees it. See [Authentication](/features/signing-in/).
- Sessions are per run. A `[E2ESetup]` test saves state under a name, and `[E2ESession]` restores it. The file is encrypted, kept under `.e2e/sessions/<run id>`, and deleted at cleanup, so there is no `.auth/user.json` to reuse across runs.
- No raw `IPage` in tests. Nothing on a raw page is recorded, redacted, or masked.

| Setting | Playwright .NET | e2e |
