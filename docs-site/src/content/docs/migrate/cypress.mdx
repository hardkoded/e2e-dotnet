This guide ports upstream's `docs/migrate/cypress.mdx` (tester-army/e2e at `7b1b8b27`, tester-army/e2e#1441). Cypress runs in Node and the port runs in .NET, so a Cypress project gets a new .NET test project beside it. Cypress component testing has no e2e equivalent: leave those specs in Cypress.

e2e replaces Cypress command chains with async C# tests that run with `dotnet test`. Both suites can stay in the repository while you move one spec at a time.

## Agent prompt

```text
Migrate this project's Cypress tests to e2e, one spec at a time. Docs: the "From Cypress" page of the e2e-dotnet docs site (docs-site/src/content/docs/migrate/cypress.mdx).

1. Read the migration guide. It maps Cypress config, commands, and assertions to e2e, and lists what e2e doesn't have yet.
2. Ask me where the .NET test project should live and whether to use NUnit or xUnit v3. If the repository has none, run `e2e init <directory> --yes` (add `--framework xunit` for xUnit v3). It creates the test project and example test, writes e2e.config.json, and installs the skill. In an existing test project it adds the missing package references to the .csproj.
3. Read the e2e skill (`e2e guide` prints it, `e2e guide <topic>` prints a topic) and follow it for every step below.
4. If you ran init, ask me which model to use for agent steps. If it needs a sign-in, give me the `e2e login <provider>` command and wait until I confirm.
5. Port cypress.config.* into e2e.config.json: baseUrl and the dev server command become the target's app, and if the specs select by data-cy, set WebEngineOptions.TestIdAttribute = "data-cy" so Screen.GetByTestId reads it. Keep Cypress installed while both suites run.
6. List the Cypress end-to-end specs and ask me which one to move first. Suggest one that breaks often or waits with cy.wait(ms). Component tests have no e2e equivalent; leave them in Cypress.
7. Rewrite that spec as a test class that derives from E2ETest with the guide's tables, one awaited call per line. Before you port a test, check "What e2e doesn't have yet": use the "Use today" workaround, or leave the test in Cypress and say why. Where cy.contains matched a fragment, pass exact: false. Replace each cy.wait(ms) with an assertion on the state the test waits for.
8. Keep navigation and the final assertions deterministic, with App.OpenAsync and Expect.That. Where a run of scripted interactions breaks often, propose an Agent.ActAsync goal for it instead.
9. Run the new class with `dotnet test --filter` and fix it until it passes. Keep the Cypress spec until I confirm it can go.
10. Summarize which tests moved, which stayed in Cypress, and why.
```

For a migration that spans several sessions, the `migrate-to-e2e` skill records what moved in a progress file and keeps the old suite running until you retire each test. See [Coding agents](/coding-agents/#migrate-an-existing-suite).

## Port the config

Install e2e and configure a model with the [web guide](/get-started/web/). The example below uses an agent call.

| Cypress | e2e |
| --- | --- |
| `baseUrl`, `start-server-and-test` | `app.url` with `app.command` on the target, see [Web](/get-started/web/) |
| `data-cy` selectors | `WebEngineOptions.TestIdAttribute = "data-cy"`, then `Screen.GetByTestId` |
| `viewportWidth`, `viewportHeight`, `cy.visit(url, { auth, headers })` | `WebEngineOptions.Viewport`, `BasicAuth`, `Headers` |
| `retries: { runMode: 2, openMode: 0 }` | NUnit `[Retry(3)]`, which counts attempts; xUnit v3 has no retry attribute |
| `env`, `Cypress.env()`, `cypress.env.json` | `Environment.GetEnvironmentVariable`; sign-in values go in `credentials` and `secrets`, see [Authentication](/features/signing-in/) |
| `cypress run --browser firefox` | A target with `WebEngineOptions.BrowserName = BrowserName.Firefox` |

```json title="e2e.config.json"
{
  "targets": [{ "name": "web", "platform": "web", "app": { "url": "http://localhost:3000" } }]
}
```

```csharp title="TodoTests.cs"
using E2E.NUnit;

public sealed class TodoTests : E2ETest
{
    protected override IEngine CreateEngine() => new WebEngine(new WebEngineOptions
    {
        TestIdAttribute = "data-cy",
    });
}
```

## Rewrite one spec

Start with a spec that often breaks.

```js title="Cypress"
describe('todos', () => {
  it('completes one', () => {
    cy.visit('/todos');
    cy.get('[data-cy=new-todo]').type('Buy milk{enter}');
    cy.get('[data-cy=new-todo]').type('Walk the dog{enter}');
    cy.contains('li', 'Buy milk').find('[data-cy=toggle]').click();
    cy.get('[data-cy=todo]').should('have.length', 2);
    cy.contains('1 item left').should('be.visible');
  });
});
```

```csharp title="e2e (NUnit)"
using E2E.NUnit;

public sealed class TodoTests : E2ETest
{
    protected override IEngine CreateEngine() => new WebEngine(new WebEngineOptions { TestIdAttribute = "data-cy" });

    [Test]
    [Category("RealModel")]
    public async Task Completes_one()
    {
        await App.OpenAsync("/todos");
        await Agent.ActAsync("add todos \"Buy milk\" and \"Walk the dog\"");
        await Expect.That(Screen.GetByTestId("todo")).ToHaveCountAsync(2);
        await Agent.ActAsync("complete \"Buy milk\"");
        await Expect.That(Screen.GetByText("1 item left")).ToBeVisibleAsync();
    }
}
```

For xUnit v3, use `E2E.XUnit.V3`, `[Fact]`, and `[Trait("TestCategory", "RealModel")]`.

## Map each command

| Cypress | e2e |
| --- | --- |
| `cy.visit(path)`, `cy.reload()`, `cy.viewport(w, h)`, `cy.setCookie()` | `App.OpenAsync(path)`, `Browser.ReloadAsync()`, `Browser.SetViewportAsync(...)`, `Browser.SetCookiesAsync(...)` |
| `cy.get('[data-cy=x]')`, `.find('[data-cy=x]')` | `Screen.GetByTestId("x")`, `row.GetByTestId("x")` |
| `cy.get('css')` | `Browser.Locator("css")`, web only; prefer a role or label |
| `cy.contains('text')`, `cy.contains('li', 'text')` | `Screen.GetByText("text", exact: false)`, `Screen.GetByRole("listitem").Filter("text")` |
| `.click()`, `.dblclick()`, `.clear()`, `.check()`, `.uncheck()`, `.focus()`, `.first()`, `.last()`, `.scrollIntoView()` | `.TapAsync()` (or `.ClickAsync()`), `.DoubleTapAsync()` (or `.DblClickAsync()`), `.ClearAsync()`, `.CheckAsync()`, `.UncheckAsync()`, `.FocusAsync()`, `.First()`, `.Last()`, `.ScrollIntoViewAsync()` |
| `.rightclick()`, `.eq(n)`, `.selectFile(path)` | `.SecondaryTapAsync()`, `.Nth(n)`, `.SetInputFilesAsync(path)` |
| `.type('text')`, `.type('{enter}')`, `.clear().type('text')` | `.PressSequentiallyAsync("text")` appends with key events, `.PressAsync("Enter")`, `.FillAsync("text")` |
| `.select('Pro')` | `.SelectOptionAsync("Pro")` matches the label; a value or an index needs the option object |
| `.should('be.visible')`, `be.checked`, `be.disabled`, `be.focused`, `exist` | `await Expect.That(locator).ToBeVisibleAsync()`, `ToBeCheckedAsync()`, `ToBeDisabledAsync()`, `ToBeFocusedAsync()`, `ToBeAttachedAsync()` |
| `have.text`, `contain`, `have.value`, `have.attr`, `have.length`, `not.exist` | `ToHaveTextAsync`, `ToContainTextAsync`, `ToHaveValueAsync`, `ToHaveAttributeAsync`, `ToHaveCountAsync(n)`, `ToHaveCountAsync(0)` |
| `cy.url().should('include', p)`, `cy.title()` | `Expect.That(Browser).ToHaveURLAsync(new Regex("p"))`, `Expect.That(Browser).ToHaveTitleAsync(t)` |
| `cy.intercept('/api/users', body)` | `Browser.RouteAsync("**/api/users", route => route.FulfillAsync(new RouteFulfillResponse { Json = body }))`, a glob on the full URL |
| `cy.on('window:confirm')`, `cy.on('window:alert')` | `await Browser.OnDialogAsync(DialogHandler.Accept)` before the action, `DialogHandler.Dismiss` to cancel |
| `cy.session` | `[E2ESetup]` and `[E2ESession]` |
| `cy.task`, `cy.exec`, `cy.request`, `cy.fixture` | .NET code: `HttpClient`, `File`, your database client, a file read such as `File.ReadAllTextAsync` |
| `Cypress.Commands.add` | A method on the test class or a base class |
| `cypress open` | `E2E_HEADLESS=0 dotnet test`, plus `E2E_DEBUG=1` for the step table |

## What e2e doesn't have yet

Planned gaps are on the roadmap, and Not yet gaps have no date. Not planned gaps are left out on purpose.

### Planned

| Cypress | Use today |
| --- | --- |
| `.find('css')`, `.filter('css')`, `.not('css')` | Chain a `GetBy*` query, or write one selector: `Browser.Locator("li.active >> .title")` |
| `.invoke()`, `.its()`, `.then($el => ...)`, `.should($el => ...)` | `GetAttributeAsync()`, `TextContentAsync()`, `InputValueAsync()`, else `Browser.EvaluateAsync<T>` |
| `have.class`, `have.css`, `have.prop`, `be.empty` | `Expect.That(Browser).ToHaveClassAsync(locator, new Regex("..."))`, `Expect.That(locator).ToHaveTextAsync("")`; else read the value with `Browser.EvaluateAsync<T>` |
| `.trigger()`, `cy.scrollTo()`, `.blur()` | `HoverAsync()`, `DragToAsync()`, `ScrollIntoViewAsync()`, `PressAsync("Tab")`; else `Browser.EvaluateAsync<T>` |
| `cy.intercept('POST', url)` and other method or header matchers | Check `route.Request.Method` in the handler, else call `route.FallbackAsync()` |
| `cy.wait('@alias')`, `.its('request.body')`, `@alias.all` | Start `Browser.WaitForResponseAsync(pattern)` before the action; read the request in a `Browser.RouteAsync` handler |
| `Cypress.on('uncaught:exception')` | An app error doesn't fail a test. To fail on one, collect `window.onerror` in `Browser.AddInitScriptAsync`, then assert the list is empty with `Browser.EvaluateAsync<T>` |
| `--browser chrome`, `edge`, `electron`, `before:browser:launch` | `BrowserName.Chromium`, or attach to your own Chrome with `WebEngineOptions.Connect` |
| `cypress open`, time-travel snapshots | `E2E_HEADLESS=0 dotnet test` with `E2E_DEBUG=1`. The port has no trace page, `--watch`, or `--step` |
| `before()` and `after()` that drive the app, `describe.only` | UI setup in `[SetUp]` (NUnit) or `InitializeAsync` (xUnit), cleanup in `[TearDown]` or `DisposeAsync`; sign-in in an `[E2ESetup]` that saves a session; `[Explicit]` or a `--filter` on the test |
| `cy.clock()`, `cy.tick()` | A fake-timers script loaded with `Browser.AddInitScriptAsync`, driven by `Browser.EvaluateAsync<T>` |
| `cy.request()` with the browser's cookies | Send the cookies from `Browser.CookiesAsync()` with `HttpClient` |

### Not yet

| Cypress | Use today |
| --- | --- |
| `supportFile`, `blockHosts` | A base class that every test class derives from; abort hosts there with `Browser.RouteAsync` |
| `cypress run --record --parallel`, Cypress Cloud | The framework's parallelism and its CI test logger; the port has no `--shard` |
| `cy.visit()` failing on a 4xx or 5xx page | `App.OpenAsync` ignores the status. Assert on the page content |
| `cy.stub()`, `cy.spy()`, `cy.clearLocalStorage()` | Wrap the function in `Browser.AddInitScriptAsync`; read calls or clear storage with `Browser.EvaluateAsync<T>` |

### Not planned

| Cypress | Use instead |
| --- | --- |
| `cy.wait(ms)` | A locator assertion on the state the test waits for |
| `it`, `context`, `specify`, `xit` | `[Test]` or `[Fact]`, a test class, `[Ignore]` or `[Fact(Skip = "...")]` |
| chai `expect(x).to...`, `assert.*` | Your framework's assertions (`Assert.That`, `Assert.Equal`) on the value |
| `cy.window()`, `cy.document()`, `onBeforeLoad(win)` | `Browser.EvaluateAsync<T>` and `Browser.AddInitScriptAsync` with JSON values. Tests run in .NET, not in the page |
| Mocha reporters, `reporterOptions` | The test framework's loggers and result files |
| Cucumber `.feature` files, `file:preprocessor` | Rewrite features as tests |
| Component testing | Keep it in Cypress. e2e tests a running app |
| `.parent()`, `.closest()`, `.siblings()`, `.next()` | Locate the ancestor and narrow it: `card.Filter(child)` |
| `{ force: true }` | Act on the visible label, or `TapAsync` with a position, which skips the actionability checks |

## What differs on purpose

- There is no command chain. Await each call and keep the locator or value in a variable, where Cypress uses `.as()`, `.within()`, or `.then()`.
- Locators are strict. An action or single-node assertion on several matches fails with `LOCATOR_AMBIGUOUS`. Narrow with `Filter(...)`, `First()`, or `Nth(n)`, or loop over `await locator.AllAsync()`.
- A string in a query matches the whole text. `exact: false` matches a fragment in any case. `cy.contains` is case-sensitive and takes the first match, so pass a Regex or add `.First()`.
- Text matchers compare the rendered text. CSS `text-transform` applies and hidden children are left out.
- Dialogs are not accepted for you. An `alert` or `confirm` with no handler fails the next step, where Cypress accepts it.

## Defaults that differ

| Setting | Cypress | e2e |
| --- | --- | --- |
| Viewport | 1000 by 660 | 1280 by 720 |
| Action and assertion timeouts | `defaultCommandTimeout`, 4 s | `actionTimeout` 30 s, `assertionTimeout` 5 s |
| Retries in CI | `0` | The framework's retry attribute, none by default |
