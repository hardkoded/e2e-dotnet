This guide ports upstream's `docs/migrate/selenium.mdx` (tester-army/e2e at `7b1b8b27`, tester-army/e2e#1441). Upstream's example is Java and its target is TypeScript. This guide maps Selenium `WebDriver` for .NET (`Selenium.WebDriver`, with NUnit or xUnit) to C# e2e tests.

e2e replaces a Selenium suite with C# tests. Locators find nodes by role and label, and assertions retry until they pass or time out. Run both suites and move one flow at a time.

## Agent prompt

```text
Migrate this project's Selenium .NET tests to e2e, one flow at a time. Docs: the "From Selenium .NET" page of the e2e-dotnet docs site (docs-site/src/content/docs/migrate/selenium.mdx).

1. Read the migration guide. It maps Selenium config and WebDriver calls to e2e, and lists what e2e doesn't have yet.
2. e2e tests are NUnit or xUnit v3 tests. If the Selenium suite uses another language, ask me where the new test project should live.
3. If the solution has no e2e test project, run `e2e init <directory> --yes` beside the Selenium project (add `--framework xunit` for xUnit v3). It creates the test project and example test, writes e2e.config.json, and installs the skill. In an existing test project it adds the missing package references to the .csproj.
4. Read the e2e skill (`e2e guide` prints it, `e2e guide <topic>` prints a topic) and follow it for every step below.
5. If you ran init, ask me which model to use for agent steps. If it needs a sign-in, give me the `e2e login <provider>` command and wait until I confirm.
6. Set the target's app.url to the URL every driver.Navigate().GoToUrl used, and app.command to the command that starts the app if the suite starts it. Move passwords and tokens into credentials or secrets.
7. List the page objects and the flows that use them, and ask me which to move first. Suggest one page object and its flows.
8. Rewrite those flows as test classes that derive from E2ETest, with the guide's tables. Check "What e2e doesn't have yet" before you port a flow. If it lists a call the flow needs, use the "Use today" workaround, or leave the flow in Selenium and say why. Prefer role, label, and test id queries over CSS and XPath. Replace every wait and Thread.Sleep with a locator assertion. Narrow queries that match several nodes. Turn the page object's setup code into a [SetUp] (NUnit) or InitializeAsync (xUnit).
9. Keep navigation and the final assertions deterministic, with App.OpenAsync and Expect.That. Where a run of scripted interactions breaks often, propose an Agent.ActAsync goal for it instead.
10. Run the new classes with `dotnet test --filter` and fix them until they pass. Keep the Selenium tests until I confirm they can go.
11. Summarize which flows moved, which stayed in Selenium, and why.
```

For a migration that spans several sessions, the `migrate-to-e2e` skill records what moved in a progress file and keeps the old suite running until you retire each test. See [Coding agents](/coding-agents/#migrate-an-existing-suite).

## Port the config

Install e2e with the [web guide](/get-started/web/). Only agent calls need a model, so the example below runs without one.

| Selenium | e2e |
| --- | --- |
| The URL in every `Navigate().GoToUrl` | `app.url` on the target, then relative paths |
| Starting the app in a script | `app.url` with `app.command`, see [Web](/get-started/web/) |
| One driver per browser | One target per `WebEngineOptions.BrowserName` build, `Chromium`, `Firefox`, or `Webkit`, not Chrome, Edge, or Safari |
| Selenium Grid | The framework's parallelism, a [browser provider](/features/browser/#hosted-browsers) for hosted Chromium |
| Passwords from `Environment.GetEnvironmentVariable` | `credentials` or `secrets` in the config, see [Authentication](/features/signing-in/) |
| `Manage().Window.Size` | `WebEngineOptions.Viewport` |
| A page object for sign-in | `[E2ESetup]` and `[E2ESession]`, see [Authentication](/features/signing-in/) |

## Rewrite one flow

```csharp title="Selenium .NET"
driver.Navigate().GoToUrl("http://localhost:3000/login");
var wait = new WebDriverWait(driver, TimeSpan.FromSeconds(10));
wait.Until(ExpectedConditions.ElementIsVisible(By.Id("username"))).SendKeys("admin@example.test");
driver.FindElement(By.Id("password")).SendKeys(Environment.GetEnvironmentVariable("ADMIN_PASSWORD"));
driver.FindElement(By.XPath("//button[contains(., 'Sign in')]")).Click();
wait.Until(ExpectedConditions.UrlContains("/dashboard"));
Assert.That(driver.FindElement(By.CssSelector(".greeting")).Text, Is.EqualTo("Welcome back, admin!"));
```

```csharp title="e2e (NUnit)"
using E2E.NUnit;

public sealed class SignInTests : E2ETest
{
    [Test]
    public async Task Signs_in()
    {
        var admin = Credentials.User("admin");
        await App.OpenAsync("/login");
        await Screen.GetByLabel("Username").FillAsync(admin.Username);
        await Screen.GetByLabel("Password").FillAsync(admin.Password);
        await Screen.GetByRole("button", "Sign in").TapAsync();
        await Expect.That(Browser).ToHaveURLAsync("/dashboard");
        await Expect.That(Screen.GetByRole("status")).ToHaveTextAsync("Welcome back, admin!");
    }
}
```

For xUnit v3, use `E2E.XUnit.V3` and `[Fact]`. The body is the same. Locator actions wait for their targets, so no explicit wait is left. The password comes from `E2E_USER_ADMIN_USERNAME` and `E2E_USER_ADMIN_PASSWORD` or the `credentials` key, see [Authentication](/features/signing-in/).

## Map each WebDriver call

| Selenium | e2e |
| --- | --- |
| `driver.Navigate().GoToUrl(url)`, `Navigate().Back()`, `.Forward()`, `.Refresh()` | `App.OpenAsync(path)`, `App.BackAsync()`, `Browser.ForwardAsync()`, `Browser.ReloadAsync()` |
| `driver.Url`, `driver.Title`, `Manage().Cookies.AddCookie`, `GetScreenshot()` | `Browser.UrlAsync()`, `Browser.TitleAsync()`, `Browser.SetCookiesAsync`, `App.ScreenshotAsync("label")` |
| `By.Id("x")` | `Browser.Locator("#x")`, or `"[id=\"x\"]"` when the id has `:`, `.`, `$`, or a leading digit |
| `By.Name`, `By.CssSelector`, `By.XPath` | `Browser.Locator("[name=\"x\"]")`, `Browser.Locator("css or xpath")` |
| `By.LinkText`, `By.PartialLinkText` | `Screen.GetByRole("link", name)`, `exact: false` for part of the name |
| `FindElements(...).Count`, `FindElements(...)[n]` | `await locator.CountAsync()`, `locator.Nth(n)` |
| `.Click()`, `.Clear()`, `Actions.MoveToElement`, `Actions.DragAndDrop` | `.TapAsync()` (or `.ClickAsync()`), `.ClearAsync()`, `.HoverAsync()`, `.DragToAsync(target)` |
| `.SendKeys("text")` | `.FillAsync("text")` replaces the content, `.PressSequentiallyAsync("text")` appends |
| `.SendKeys(Keys.Enter)`, `Actions.KeyDown(Keys.Control).SendKeys("a")` | `.PressAsync("Enter")`, `.PressAsync("ControlOrMeta+a")` |
| `.SendKeys(path)` on a file input, `new SelectElement(el).SelectByText` | `.SetInputFilesAsync(path)`, `.SelectOptionAsync("label")` |
| `.Text`, `.Displayed`, `.GetDomAttribute(name)` | `.TextContentAsync()`, `.IsVisibleAsync()`, `.GetAttributeAsync(name)` |
| `.GetAttribute("value")`, `.GetAttribute("checked")` | `.InputValueAsync()`, `.IsCheckedAsync()`. e2e's `.GetAttributeAsync()` reads the DOM attribute, not the property |
| `wait.Until(ElementIsVisible(...))`, `d => el.Text == "x"`, `UrlContains(...)` | `Expect.That(locator).ToBeVisibleAsync()`, `.ToHaveTextAsync("x")`, `Expect.That(Browser).ToHaveURLAsync(new Regex("..."))` |
| `SwitchTo().Frame()`, `SwitchTo().Alert().Accept()` | `Browser.FrameLocator("#frame")`, `await Browser.OnDialogAsync(DialogHandler.Accept)` before the action |
| `SwitchTo().Window(handle)`, `WindowHandles`, `SwitchTo().NewWindow()` | `tab.ActivateAsync()`, `Browser.Tabs`, `Browser.NewTabAsync()`; `Browser.WaitForPopupAsync(() => trigger)` for a tab the app opens |
| `ExecuteScript(script, args)` | `Browser.EvaluateAsync<T>(fn, arg)`, JSON in and out only |
| Page objects | A class that takes `Screen` and `Browser`, or a goal for `Agent.ActAsync`, see [Migrating from Playwright .NET](/migrate/playwright/#port-page-objects) |

## What e2e doesn't have yet

Planned means on the roadmap, and Not yet means no date. Not planned means e2e leaves it out on purpose.

### Planned

| Selenium | Use today |
| --- | --- |
| `ExecuteScript(script, element)`, `GetDomProperty`, `GetCssValue` | A locator action such as `.TapAsync()` or `.ScrollIntoViewAsync()`, or `Browser.EvaluateAsync<T>` with a CSS selector |
| `element.FindElement(By.CssSelector)` | One `Browser.Locator("a >> b")` selector, or chained `GetBy*` queries |
| `ChromeOptions.AddArguments`, `BinaryLocation`, `Proxy`, `AcceptInsecureCerts` | Start Chrome or Edge with the flags, then attach with `WebEngineOptions.Connect` |
| `[OneTimeSetUp]` and `[OneTimeTearDown]` for the whole run, xUnit collection fixtures | Once for the run: the script `app.command` starts, or a wrapper around `dotnet test`. Once for a class: `[OneTimeSetUp]` or `IAsyncLifetime`. Sign-in: an `[E2ESetup]` that saves a session |
| BrowserStack or Sauce Labs for web | Your own [browser provider](/features/browser/#hosted-browsers), if the vendor has a CDP endpoint |
| `Manage().Logs`, request listeners, geolocation | Patch the page in `Browser.AddInitScriptAsync`, record requests in `Browser.RouteAsync` |
| `NetworkConditions` | For offline, abort requests in `Browser.RouteAsync`. No throttling or latency, keep those tests in Selenium |

### Not yet

| Selenium | Use today |
| --- | --- |
| `new RemoteWebDriver(gridUrl)`, Firefox or Safari on remote nodes | `WebEngineOptions.Connect` to a CDP endpoint. Run `Firefox` and `Webkit` targets locally |
| Two drivers in one test | Drive the second user through the app's API |
| `PageSource`, local storage, session storage | `Browser.EvaluateAsync<T>`, such as `() => localStorage.getItem('k')` |

### Not planned

| Selenium | Use instead |
| --- | --- |
| SpecFlow or Reqnroll feature files | Rewrite each scenario as a test. A step often fits one `Agent.ActAsync` goal |
| `Thread.Sleep`, `Actions.Pause`, `ExpectedConditions.ElementToBeClickable(...)` | A locator assertion on the state you wait for. Each action waits for its node |
| `SwitchTo().Alert()` after the dialog opens, `AlertIsPresent()` | `Browser.OnDialogAsync(handler)` before the action that opens it |
| Real Safari, IE mode | `Webkit` is the closest build to Safari. Keep IE mode tests in Selenium |
| `ExecuteCdpCommand`, `DevTools` sessions, SDKs that take the driver | Keep those tests in Selenium. A raw driver call isn't recorded or redacted |
| Allure reports | Feed the test framework's result files to Allure |

## What differs on purpose

- `FindElement` takes the first match. e2e fails with `LOCATOR_AMBIGUOUS` on several, so narrow with `Filter(...)`, `First()`, or `Nth(n)`.
- There is no implicit wait. Actions and assertions wait on their own, up to `actionTimeout` and `assertionTimeout`.
- Each test gets a fresh browser context, not a shared driver. To sign in one time, use `[E2ESetup]` and `[E2ESession]`, see [Authentication](/features/signing-in/).
- The page size comes from `WebEngineOptions.Viewport`, not `Size` or `Maximize()`.
